# Shion（诗音）完整规格

> 中文名诗音，日文名詩音（しおん），英文名 Shion。她在台词里会用这个名字称呼自己。
> 非官方粉丝作品，与 Anthropic 无关。

## 技术栈

- Python 3.10+，GUI 用 **PySide6**
- 虚拟环境：`.venv`（`python -m venv .venv`，然后 `.venv\Scripts\pip install -r requirements.txt`）
- 依赖尽量少：`PySide6`、`pytest`；`numpy`、`scipy`、`pillow` 只给素材脚本用。hook 脚本**只能用标准库**。

## 素材

`assets/sprites/` 里有 12 张状态图和动作帧（jump 4、drag 4、turn 8、tickle 3、cheek 3、bed 2、desk 3）。普通图和 desk 为 448×512，bed 为 640×512；脚底基线一致。walk_1～8 及源图保留在仓库，运行时不加载、不播放。idle 人物 alpha 边界约为 (43, 24)～(401, 504)，实际交互区按下面的画布比例划分。

处理脚本 `tools/process_sprites.py`：不依赖固定坐标，把 `raw/` 的原图清理 alpha 去毛边；以 idle 为基准把站立图的人物高度统一到 480，坐着/悬空的图（sleep/drag/neglect2）用站立图的平均缩放比例；脚底贴底，水平按头部（上部 40%）重心居中，切换表情时头不跳；个别图用 `EXTRA_SCALE` 手动微调。

`tools/process_sheets.py` 处理 raw 下 walk / jump / drag / turn / tickle / cheek 分帧图，预期帧数为 8 / 4 / 4 / 8 / 3 / 3；普通状态脚本跳过 `*_sheet`。turn 使用首帧头宽与整组身高的折中比例，并限制最高帧不超出画布。运行时 jump / drag 继续按实际连续数字编号加载任意帧数；turn / tickle / cheek 分别必须完整提供 8 / 3 / 3 帧，且整组可解码、组内画布一致、高度与 idle 一致（允许不同宽度）。每组独立回退：转身/朝向缺图不执行，捏脸回退 stop，挠痒回退 happy 加左右扭动；不生成镜像。

同一脚本也处理 bed / desk（2 / 3 帧），带道具按整体边界居中，`WIDE` 指定各自画布宽度。运行时同组帧须完整、同尺寸且高度与 idle 相同，宽度允许不同；bed 缺图/坏图回退 sleep，desk 回退 neglect1，互不影响。

## 窗口

- 无边框、背景透明、始终置顶、不在任务栏显示：`FramelessWindowHint | WindowStaysOnTopHint | Tool`，加上 `WA_TranslucentBackground`。
- 默认显示高度 **200px**（图片按比例缩放，用平滑缩放）。右键菜单可以调成 160 / 200 / 260 / 320。
- 默认位置：主屏幕可用区域（`availableGeometry`，不含任务栏）的右下角，脚底贴着底边。
- 动作画布按原比例缩放至指定高度，宽度随动作变化，脚底中心保持不动；贴边时优先把本体夹进屏内。交叉淡化按各图自己的宽度、脚底中心对齐，不拉伸；过渡结束才收窄画布。绘制、遮罩、气泡/面板跟随共用当前本体尺寸。
- 透明像素要能**点击穿透**。Windows 的分层窗口一般会自动穿透，务必实测确认。如果不行，用 `setMask` 根据当前帧的 alpha 生成遮罩。
- 只允许运行一个实例：用 `QLocalServer`/`QLocalSocket` 检测，第二个实例启动后直接退出。

## 程序动画（animator.py）

- **呼吸**：idle、neglect1 状态下，纵向缩放在 1.000 和 1.012 之间正弦变化，周期 3 秒，以脚底为锚点。
- **眨眼**：idle 状态下每隔 3～6 秒（随机）切到 blink 120ms；有 15% 的概率连续眨两次。
- 所有缩放、倾斜都以**脚底中心**为锚点，避免人物飘起来。
- 动画计时器用 `Qt.PreciseTimer`；桌宠、气泡、粒子按 `time.perf_counter()` 的实际经过时间计算，掉帧后直接到达对应时刻；下落使用重力位置解析式，不截断经过时间。
- 切换精灵使用约 120ms 的 ease-out 交叉淡化，附带约 3% 的压扁和轻微回弹；快速切换时从当前混合画面接续，缩放、角度也从当前姿态缓动，脚底锚点保持固定。眨眼的淡化不附加压扁。
- 动作序列在显示层覆盖底层表情，序列内部直接按经过时间取帧，不对每一帧做状态淡化。结束或中断后恢复当前底层状态；绘制与遮罩使用同一动作帧和位移，掉帧不拖慢动作。落地回弹以预定落地时刻计时。
- 粒子位移使用三次 ease-out，拖动倾斜使用指数 ease-out，压扁使用先压缩后回弹的平滑曲线；鼠标拖动位置仍直接跟随用户输入，下落保持非线性重力加速。
- 待机动作由独立行为调度器控制。Claude 工作中、固定表情、睡眠和安静档只保留适用的呼吸/眨眼，关闭摆动；独立 blink 图仅用于 idle。绘制和遮罩共用当前原始动作帧及脚底锚点，不创建镜像缓存。所有序列按真实经过时间取帧，掉帧不拖长转身或侧身的持续时间。
- 遮罩按量化后的姿态缓存，淡化时取两张图的可见区域并集；仅透明度变化时复用遮罩。每次只绘制一遍，再平移合并区域扩边。

## 状态机（state.py）

优先级从高到低（高优先级的临时状态结束后，回到底层状态）：

1. **drag**：正在被拖动
2. **固定表情 / 手动表情**：固定无期限；未固定的手动表情 5 秒
3. **临时反应**（有持续时间）：happy、stop、dizzy、done（3 秒）、proud（3 秒）
4. **working**：按会话（session_id）计算，任意一个会话在工作就显示。会话从 UserPromptSubmit / PreToolUse 开始算工作中；PreToolUse 之后、对应的 PostToolUse / PostToolUseFailure（按 tool_use_id 配对）之前一直保持（单个工具最长 30 分钟）；没有在执行的工具时，距最近事件 5 分钟（调试模式 60 秒）才退出。这个会话 Stop / plan_ready / 被中断或停太久结束 / Notification `idle_prompt` 时立刻退出；别的会话还在工作时，done 3 秒之后回到 working。plan_ready 只提醒看计划，不计为完成任务、不触发 done 或完成后的定时催促
5. **sleep**：本地时间 0:30～6:30，或者 15 分钟没有实际鼠标操作、也没有 Claude 事件。实际交互按原规则唤醒，唤醒时说一句起床台词；悬停与浏览/取消右键菜单不唤醒、不延后入睡
6. **待机短暂表情**：happy / idle 2 秒
7. **底层状态**：根据冷落值决定
   - 距离上次“被理会”（摸头、点击、或任意 Claude 事件）**< 30 分钟** → idle
   - **30 分钟～2 小时** → neglect1
   - **> 2 小时** → neglect2
   - 从 neglect2 回到 idle 时，说一句特别的台词（例：`> ……你终于回来了。`）
   - 阈值写在配置里，方便调整

好感度：整数，只增不减（摸头 +1，做得好 +3，吃完零食 +2），目前只在双击状态里显示，后续可以用来解锁台词。预设对话不增加好感度或摸头统计。

## 对话气泡（bubble.py）

- 独立的无边框置顶小窗口，跟随在桌宠头顶上方；如果靠近屏幕边缘，自动翻到另一侧。
- **终端风格**：背景 `#0A0A0A`，1px 橙色 `#F58236` 边框，圆角 4px，米白色文字，等宽字体（优先 `Cascadia Mono`，回退到 `Consolas`），每行开头加 `> `。
- 打字机效果：每 30ms 出一个字，全部显示完后停留 4 秒再淡出（0.3 秒）。
- 台词统一经控制器仲裁：高优先级（完成提醒、计划写好提醒、出错、催促、等待确认和授权请求）随时打断；中优先级（问候、唤醒/回归、菜单反馈、双击状态查询）只能打断低优先级；低优先级（摸头、戳、拖、自言自语、工作过程提示）不能打断中/高。当前气泡自然消失后不再阻挡。
- 低优先级互相替换时，当前气泡须已出现至少 2.5 秒（从气泡开始出现计时，不从打字完成计时），且同一触发类别已实际说出的台词至少间隔 4 秒；戳导致的普通/挡手/晕共用戳冷却，拖动及其落地晃晕共用拖冷却。被拦截的台词丢弃，不补播，不消耗随机台词选择。
- 三语原生提供 cheek_pull / cheek_release / tickle / tickle_end，各至少三句，保持傲娇语气。cheek_pull、tickle 属低优先级；松手生气与停止后的喘气属中优先级，可接替刚发生的互动台词；静音及中/高优先级工作消息仍照常仲裁，不排队补播。
- 相邻摸头间隔 ≤1 秒算同一过程：开始尝试说一句，连续持续超过 6 秒再尝试一句，同一过程最多两句；仍受低优先级规则限制。每次摸头的爱心、表情、好感度及统计照常。相关时间都在 `speech.py`。
- 台词从当前语言的 json 随机抽取，同一类台词不要连续重复。静音时不弹气泡。
- 气泡字体：首选等宽字体不变，后面追加当前语言 `meta.font_fallback` 里已安装的字体（日文、中文字符走它）。

## 本地通信协议（server.py）

- 监听 **`127.0.0.1:47613`**，只绑定本机。用标准库 `http.server` 在后台线程运行，通过 Qt 信号把事件转发给 GUI 线程，**不能在后台线程里直接操作界面**。
- `POST /event`，请求体为 `{"type": "...", "detail": "可选"}`

| type | 来源 | 桌宠行为 |
|---|---|---|
| `session_start` | SessionStart hook | 说一句问候，刷新“被理会”时间 |
| `prompt` | UserPromptSubmit hook | 刷新“被理会”时间 |
| `working` | PreToolUse hook | 进入 working（已经在 working 时不重复说话），记下在执行的工具 |
| `tool_done` | PostToolUse hook（放行后）；PostToolUseFailure 的 Esc 中断 | 工具执行完，不说话 |
| `stop` | Stop hook | 退出 working → 播放 done 3 秒 + claude_done 台词，claude_tasks +1。**例外**：这个会话的这一轮刚被诗音结束（立即中断、检查点拿到 stop 即 `work_stopped`、`pause_timeout`）时，紧接着的那次 Stop 按 work_stopped 处理：不加 claude_tasks、不显示 done、不说完成台词、不催、最近活动不记“做完了”，菜单仍提供“继续”；该会话再来 `prompt` 时这个标记作废 |
| `plan_ready` | ExitPlanMode 的 PermissionRequest hook | 高优先级气泡“计划写好啦，去看看吧～”并跳一下；退出 working，不弹授权面板、不计完成任务 |
| `notification` | Notification hook | 气泡提示“有事情等你确认哦”（只有终端版会触发）。`detail` 是官方字段 `notification_type`；为 `idle_prompt`（CC 回复完约 60 秒用户没输入）时，清掉这个会话的“工具在执行中”和 working（在提问框上按 Esc 等情况 CC 不发 PostToolUse / Stop），并收起这个会话还挂着的授权面板 |
| `react` | 预留（目前没有调用方） | `detail` 是表情名，临时切换到该表情 3 秒 |

- `POST /feedback/take` → 返回 `{"text": "…"}`：取走并清空反馈队列，按存档语言合成要注入的文字（没有则为空串；`inject_praise` 为 false 时仍清空但返回空串）。读取和清空是同一个原子操作
- 会话字段（`/event` 可选，`server.parse_meta` 校验，不对就 400）：`session`（stdin 的 session_id）、`tool_id`（tool_use_id），以及 prompt / PreToolUse 附带的 `proc`：`{"pid", "created"(FILETIME), "name"(只认 claude.exe/node.exe/bun.exe), "entry"(CLAUDE_CODE_ENTRYPOINT), "hooks"(hook 自己到 CC 之间的 pid，最多 8 个)}`。带会话字段时回调为 `on_event(type, detail, meta)`，否则仍是两参数
- `POST /pause/wait {"wait": 秒, "session": 可选}` → `{"paused": true|false, "stop": true|false}`：检查点长轮询。没在停下就立即返回；停下等待中最多等 `wait` 秒（上限 30），用户点“继续”立即返回 `paused: false`；等满上限（`pause_timeout`）时**此刻正在等的所有请求**都返回 `stop: true`（之后到达的请求不受影响，不留残余状态）；这个 `session` 被“立即中断”过时立即返回 `stop: true`（只生效一次，正在等的也会被唤醒）。拿到 stop 时服务线程向界面发内部事件 `work_stopped`（带 session）。hub 记录正在等的请求数，两段长轮询之间 2 秒内仍算“在等”。**没有任何接口能让 HTTP 调用方开始停下、结束这一轮或请求中断**，`/event` 里的 `work_stopped` 一律 400；`prompt` 事件到达时服务线程直接解除等待；`stop` 事件在没有 hook 正在等时作废没用上的停下；`prompt` / `stop` 带 session 时作废该会话没用上的中断标记
- `POST /permission/open {"tool", "detail", "session"?, "key"?}` → `{"id"}`（请求体上限放宽到 64 KB；排队上限 20，满了返回 503；`session` ≤128 字，`key` 为 ≤64 位小写十六进制，不对就 400）；`POST /permission/settle {"session", "key"?}` → `{"settled": N}`：撤掉这个会话（给了 key 就只撤指纹相同的）还在等的请求，hook 之后拿到 `gone`、不给决定；`/event` 的 `prompt` / `stop` / `notification`（`idle_prompt`）带 session 时同样撤掉该会话全部未决请求；`POST /permission/wait {"id", "wait"}` → `{"id", "status"}`，`status` 是 `pending`/`allow`/`deny`/`gone`，`allow`/`deny` 只能取一次；`POST /permission/withdraw {"id"}` 撤回。**没有任何接口、任何字段能写入 allow/deny**，决定只来自诗音界面上的按钮（有测试往所有接口和事件类型里塞各种“同意”字段，请求始终保持 pending；另有源码级测试保证只有 controller 的按钮回调会写入决定）
- `type = pause_timeout`（hook 等满上限后发来）：只在停下等待中有效，界面放掉其他并行等待的 hook（也返回 stop），提醒一次“停太久了，这一轮先结束啦，在 CC 里说一声就能接着做”（不常驻）
- `GET /health` → `{"ok": true}`
- 安全：带 `Origin` 头的请求（来自网页）和 `Host` 不是 `127.0.0.1` / `localhost` 的请求一律返回 403，不触发任何回调；读请求体有 5 秒超时。hook 脚本是普通 HTTP 客户端，不受影响。

## Claude Code hooks（v0.2）

`hooks/shion_hook.py <事件名>`：

- 只用标准库（`urllib.request`），**超时 0.5 秒**。桌宠没运行或请求失败时**静默退出、返回码为 0**，绝不能影响 Claude Code 的正常使用。
- 从 stdin 读取 hook 输入的 JSON（可以不用，但必须读完）。
- `UserPromptSubmit`：先发送 `prompt` 事件，再调用 `/feedback/take`；返回的文字非空就原样打印到 stdout（`[诗音] 用户觉得你刚才做得很好。` 等，按存档语言使用中/英/日；多次“做得好”合成一句，不写次数；摸头不产生反馈）
- 所有事件都带 `session`（和 `tool_id`）；UserPromptSubmit / PreToolUse 另带 `proc`：用 Toolhelp 快照从 hook 自己沿父进程链往上找，有 `CLAUDE_PID` 环境变量时必须在链上找到它（否则不带），没有时取最近的 claude/node/bun 祖先；进程表工具在 `shion/winproc.py`（只用标准库）
- `PostToolUse` / `PostToolUseFailure` 一进来（检查点等待之前）先调 `/permission/settle`，带 session 和 `key = sha256(json.dumps([tool_name, tool_input], sort_keys=True))` 前 32 位：工具已经跑过，说明它的授权在 CC 里答过了
- `PermissionRequest`：`/permission/open` 带 session 和同样算法的 key（官方：PermissionRequest 没有 tool_use_id，只能按工具名 + 参数配对）
- `Notification`：detail 发 `notification_type`（截短 40 字），不转发 message
- `PostToolUseFailure`：发 `tool_error`；`is_interrupt`（用户在 CC 里按 Esc）时改发 `tool_done`。**不是检查点**：实测（2.1.289）CC 不理会它返回的 `continue: false`
- `PostToolUse`：**检查点**（同 PreToolUse 的 `/pause/wait` 逻辑）。放行后先发 `tool_done`，再调用 `/feedback/take`，非空则输出 `hookSpecificOutput.additionalContext`（Claude 工作中即可收到反馈）。被立即中断或等满上限时输出 `{"continue": false, "stopReason": …}`，不取反馈（留给下一次 UserPromptSubmit）
- `PreToolUse`：**检查点**。先问 `/pause/wait`；停下等待中就按 25 秒一段一直等，直到“继续”或 `prompt` 解除；诗音没开、连不上、返回内容不对一律放行（`stop`/`paused` 必须恰好是 `true` 才算数）。被立即中断或等满上限时输出 `{"continue": false, "stopReason": …}` 并附带 `permissionDecision: deny`（保证这次工具不执行），不发 `working`；等满上限（`remote.pause_timeout`，默认 30 分钟）同样处理并发 `pause_timeout`
- `stopReason` 按存档语言取 `ui.hook_stop`（默认“用户通过诗音让这一轮工作停下，请等待用户指示”）；等满上限取 `ui.hook_stop_timeout`（默认“用户很久没有回应，这一轮先结束，请等待用户指示”）。官方文档：`continue: false` 让 Claude 在 hook 运行后完全停止处理，优先于任何事件专属的决定字段；`stopReason` 显示给用户并留在对话里；对 PreToolUse 和 PostToolUse 都有效
- `SessionStart`：如果 `/health` 不通，就启动桌宠（`.venv\Scripts\pythonw.exe -m shion`，脱离父进程，不弹出控制台窗口），然后发送 `session_start` 事件。
- `Stop`：只发送 `{"type":"stop"}`，不读取/转发 `last_assistant_message`，不打开 `transcript_path`。只说当前语言的完成提醒。
- 其他事件（`PreToolUse` 发 `working`）只负责转发。
- 配置写进**用户级** `~/.claude/settings.json` 的 `hooks` 字段，这样终端和桌面端的 Code 标签页都会加载。写之前先备份原文件，**合并而不是覆盖**用户已有的配置。另外写一个 `tools/install_hooks.py`（安装）和 `tools/uninstall_hooks.py`（卸载）。
- **转圈文字**：PreToolUse / PostToolUse 两个检查点条目带官方通用字段 `statusMessage`（“hook 运行时显示的自定义转圈文字”），取 `ui.hook_status_waiting`：中“诗音在看着～（一直停在这里就是暂停了，右键诗音点继续）”/ 英 / 日，写成平时一闪而过不奇怪、停下时一直显示也看得懂。其他事件不加。文字在**安装时**按诗音存档语言写入（`--lang zh|en|ja` 可指定）；在诗音里换语言后要重跑一次 `install_hooks.py` 才会跟着变。**转圈文字只在终端版显示**，桌面端 Code 标签页不显示 hook 的 statusMessage（已知限制，用户验收 2026-10-21，不修），桌面端靠暂停标签

## 状态感知（v0.2.1）

让诗音知道 Claude Code 正在干什么，当好状态窗口，也是 v0.3 遥控功能的“眼睛”。全部基于 hooks，只读，不打扰工作。

- **完成提醒**：Stop 只提示去看结果，中文如“做完啦！去看看结果吧～”；英文如“All done! Take a look at the results~”；日文如“終わったよ！結果を見てみてね～”。三语均有原生台词，不显示回复第一句；旧 hook 发来的 stop detail 也不显示、不记录到最近活动或控制器日志。最近活动只显示“做完了”。done 表情、任务计数和定时催促保留
- **计划提醒**：ExitPlanMode 的 PermissionRequest 仅发送无 detail 的 `plan_ready` 事件，计划正文不发送。三语分别是“计划写好啦，去看看吧～” / “The plan's ready! Take a look~” / “計画ができたよ、見てみてね～”。高优先级可打断已有气泡，同时复用菜单原地跳跃一次（静音只抑制气泡，仍跳；拖动/下落时沿用跳跃的保护，不强行中断）。不登记授权、不轮询、不输出 allow/deny，确认由 CC 自己处理
- **显示正在干什么**：PreToolUse 时根据工具名和参数生成简短描述，例如“在读 state.py……”“在跑命令……”“在改 bubble.py……”。同一个描述 3 秒内不重复弹出
- **出错反应**：工具执行失败时（PostToolUse 结果里带错误，或官方提供的失败事件），切到 dizzy 2 秒，说一句“呜……出错了”
- **催你回来**：Claude 停下后，如果 5 分钟（可配置）没有新的 UserPromptSubmit，诗音跳一下提醒；最多提醒 2 次
- **最近活动记录**：内存里保留最近 20 条事件（时间、类型、简短描述），双击状态里可以看最近 5 条；不写入存档
- **隐私开关**（右键菜单）：“只显示状态，不显示内容”。打开后不显示文件名、命令；回复内容无论开关状态都不显示

## Claude Code 遥控（v0.3）

诗音成为 Claude Code 的遥控器。**只用官方 hooks 机制，不模拟按键，不往对话里发消息。**唯一的例外是下面「这一轮结束后的继续」：终端版 CC 在用户点了菜单后，往它的控制台写一句“继续”（不切前台、不用 SendInput）。 界面文字里不出现“Claude”（见 v1.0「名称与品牌」），统一叫“工作”。

右键菜单新增“工作遥控”子菜单；需要用户决定时，诗音会主动弹出带按钮的气泡。

| 操作 | 实现 | 行为 |
|---|---|---|
| **同意 / 否决** | **PermissionRequest hook**：返回 `hookSpecificOutput.decision.behavior` 为 `allow` / `deny`（字段按官方文档确认）。hook 脚本向本地服务器长轮询，等待用户在诗音上的选择 | 气泡显示要执行的命令或要改的文件（完整显示，过长时可展开）和两个大按钮。**ExitPlanMode 例外，只提醒，计划确认由 CC 自己处理** |
| **做得好 / 有问题** | 放进**反馈队列**；送达方式见下 | “有问题”可以附一句话（单行输入框，可留空） |
| **停下 / 继续**（子菜单第一项） | **PreToolUse 和 PostToolUse 两个检查点**：hook 长轮询原地等待；“继续”放行，停太久返回 `continue: false` + `stopReason` | 见下面「停下规则」 |
| **立即中断**（第二项） | 结束 CC 进程下正在跑的工具子进程树 + 一次性中断标记，下一个检查点返回 `continue: false` | 见下面「立即中断」 |
| **继续（这一轮已结束）** | 终端版：子进程 AttachConsole + WriteConsoleInputW 写“继续”+回车；桌面端：复制到剪贴板 | 见下面「这一轮结束后的继续」 |

**同意 / 否决的安全规则**
- 决定**只能由用户在诗音界面上亲手点击产生**。本地 HTTP 服务**不提供**任何“设置决定”的接口，hook 只能“等待结果”
- 默认等待 **120 秒**（可配置）。超时后 hook 不给决定，CC 照常弹出自己的授权框。**任何情况下都不能默认同意**
- **CC 自己的授权框会同时显示**（实测 2.1.289：hook 等待期间 CC 就显示自己的框，不能关掉），两边哪边先答都可以；在 CC 里答了以后诗音面板会自动收起（见下面「排队」）
- 诗音没在运行、连不上服务器时，hook 立刻退出、不给决定，交回 CC 自己处理
- ExitPlanMode 无论有无计划、计划多长，一律不登记请求、不给决定；只尝试发送 `plan_ready`，发送失败也静默退出
- 同一时间可能有多个授权请求（例如子代理并行）：按顺序排队，一次只显示一个，显示“还有 N 个”
- 否决时附带理由“用户通过诗音否决了这个操作”
- 内容超过 12000 字（面板放不下、用户看不全）时，hook 不登记请求、不给决定，交回 CC 自己的授权框
- 威胁模型：只防网页（Origin/Host 检查）和“hook 出错/超时/诗音没开”；**不防本机已被攻破的恶意进程**（本机 HTTP 无认证：它可以占着 47613 冒充诗音、灌满排队造成拒绝服务、发 prompt 事件解除暂停），这类问题不在本版范围

**反馈队列（做得好 / 有问题）**
- 内容示例：`[诗音] 用户觉得你刚才做得很好。` / `[诗音] 用户认为刚才的改动有问题：<用户输入的话>。请重新检查。` 不加“请回复”之类的话
- 送达（只用附加上下文，不产生聊天消息）：
  - Claude 正在工作：下一次 **PostToolUse** 的 `additionalContext`（官方说明：放在工具结果旁边，Claude 下一轮会读到，不作为聊天消息显示）
  - Claude 空闲：下一次 **UserPromptSubmit** 时附加
- 多条合并成一次送达；队列最多 5 条；送达后诗音说一句“已经转告啦”
- 点的时候诗音说的话：工作中说“收到！马上转告～”/“收到！这就去转告～”（`praise_menu_working` / `feedback_bad_working`，三语）；空闲时保持“收到！下次干活时我就转告～”/“收到，我会转告的”
- 右键原有的“夸夸”菜单项并入“工作遥控 → 做得好”；原来的 `pending_praise` / `/praise/take` 已由反馈队列和 `/feedback/take` 取代（存档迁移见「持久化」）

**同意 / 否决的实现要点（v0.3 第二部分）**
- hook（PermissionRequest）：`AskUserQuestion` 不处理（那是提问不是授权）；`ExitPlanMode` 只向 `/event` 发 `{"type":"plan_ready"}`，不进入授权流程；其余工具先 `/permission/open`，再按 10 秒一段 `/permission/wait`。**只有响应是对象、`id` 对得上、`status` 恰好等于 `"allow"` 才输出 allow**；`"deny"` 输出 deny + 存档语言的理由（`ui.hook_deny`，默认“用户通过诗音否决了这个操作”）；其余一切（连不上、超时、`gone`、字段不对）都不输出任何决定。超时（存档 `remote.permission_timeout`，默认 120 秒）先撤回请求再退出。
- 显示的内容：Bash/PowerShell 显示命令（有描述则附 `# 描述`）；Edit/Write/NotebookEdit 显示文件完整路径；WebFetch 显示网址；WebSearch 显示搜索词；其他显示参数 JSON（不含已排除的 ExitPlanMode / AskUserQuestion）。最多 12000 字。**隐私模式不影响授权面板**（要决定就必须看到内容）。
- 面板（`panel.py:PermissionPanel`）：终端配色；内容区只读、约 6 行高，过长出现“展开/收起”；“还有 N 个”；“否决”“同意”两个大按钮。**不抢焦点、不响应键盘**（`WindowDoesNotAcceptFocus`，按钮子类忽略所有按键），按钮在每条请求出现后 0.6 秒内不可点。静音不影响面板，只影响那一句提示语。
- 排队：诗音每 100 毫秒从 hub 取最早的未决请求显示。用户在 CC 里自己答了以后**马上收起**：同一会话的 PostToolUse / PostToolUseFailure（同意后工具跑完，按工具名 + 参数配对）、Stop、UserPromptSubmit、Notification `idle_prompt`（否决后 CC 等输入）都会撤掉对应请求，面板收起或换下一条。兜底：hook 超过 25 秒没来轮询的请求视为已被 CC 取消。官方的 `PermissionDenied` 只在 auto 模式触发，手动否决授权框时不触发，所以不接。
- 服务端 `request_queue_size` 调到 64，并行子代理的 hook 同时连进来不会被重置。

**停下规则**（不弹面板）
- 工作遥控子菜单第一项“停下”。点了以后诗音说一次“好，马上停～”，切到挡手表情
- **下一个检查点**原地等待：调用工具之前（PreToolUse）或工具做完、开始写文字之前（PostToolUse），哪个先到算哪个。正在执行的命令不会被掐断；已经开始写的文字会写完（后面没有工具调用的长段文字拦不住，这是 hooks 机制的限制）。对所有会话生效（子代理的工具调用同样受影响）
- hook 第一次真的在检查点等着时，诗音说一次“已经停下啦～”（多个并行 hook、两段长轮询之间都不重复；不常驻）
- **暂停文字标签**：从 hook 第一次真的在检查点停住开始，诗音头顶右侧显示“暂停中 / Paused / 一時停止中”（`shion/badge.py`，独立小窗口，不会被台词盖掉；静音时也显示），直到点继续、在 CC 里说话、停满上限结束或立即中断解除停下。只是点了停下、还没到检查点时不显示。字体、背景、米白文字、橙色 1px 描边和圆角与气泡一致，按文字量宽，跟随窗口/宽画布/跳跃并夹进可用屏。悬停提示“点一下继续 / Click to continue / クリックして再開”。不抢键盘焦点，只响应左键；出现后 0.6 秒内按下无效，跨过时限再松开也不能误触；按住移出标签再松开无效。标签之外仍点穿（独立小窗口与圆角遮罩），点击复用菜单“继续”，放行所有等待检查点、收起标签并按原规则说“继续干活啦”。切换语言即时更新文字、提示和字体。
- 停下期间菜单里“停下”变成“继续”：点了就放行，无缝接着干，诗音说“继续干活啦”；还没到检查点就点 = 取消这次停下
- 其他出口：
  - 在 CC 里说话：任何一次 **UserPromptSubmit** 都解除等待
  - **30 分钟（`remote.pause_timeout`，可配置 60～1880 秒）没继续**：hook 返回 `continue: false`（PreToolUse 另带 deny）结束这一轮，其他并行等待的 hook 一起结束；诗音提醒一次“停太久了，这一轮先结束啦，在 CC 里说一声就能接着做”
  - 还没碰到检查点这一轮就自己结束了（Stop）：停下作废，不会挡住下一轮
  - 诗音没在运行、连不上服务器：hook 立刻放行，不会把 CC 卡住
- 实测（2.1.289）：`continue: false` 结束这一轮后 **不会再触发 Stop hook**，所以不会出现“做完啦”
- 静音只抑制气泡，停下照常生效

**立即中断**（工作遥控第二项，不切换窗口、不模拟键盘）
- 只对“工作中”的会话（见状态机 working）生效，没有工作中的会话时菜单项是灰的；对所有工作中的会话各做一次
- 校验 hook 报来的 CC 进程：还活着、名字和创建时间都对得上（防 PID 复用）。找不到时说“找不到正在工作的进程，先改成普通的停下啦”并退回普通“停下”
- 结束“在执行的工具开始之后才创建”的 CC 直接子进程及其子孙（先孙后子，核对创建时间）；排除 hook 进程（报来的 hook pid、可执行文件是项目 `.venv\Scripts\python.exe` 的直接子进程）。MCP 服务器等会话开始时就有的子进程不受影响。没有在执行的工具（正在写文字）时不结束任何进程
- 同时给该会话设**一次性中断标记**：下一个检查点（PreToolUse / PostToolUse）返回 `continue: false`；被结束的工具触发的 PostToolUseFailure 不消耗标记，诗音也不说“出错了”。prompt / Stop 作废没用上的标记
- 做完把会话标成空闲，下一次 prompt / PreToolUse 之前不会再发；诗音说“已经中断啦，在 CC 里说一声就能继续”，并解除停下
- 终端版和桌面端 Code 用同一种做法。**不用 Ctrl+C**：实测（2.1.289）用 `GenerateConsoleCtrlEvent` 向终端版 CC 的控制台发 Ctrl+C，CC 会在 1～4 秒内整个退出，而不是像按 Esc 那样只中断当前生成
- 限制：正在写、后面没有工具调用的文字拦不住（写完就是这一轮结束）

**这一轮结束后的继续**（实验见 `docs/experiments/send-continue.md`）
- 什么时候出现：诗音结束了某个会话的这一轮之后——立即中断后 hook 在检查点拿到 stop（`work_stopped`），或中断时正在写字、这一轮自己结束（该会话的 `stop`），或停满上限（`pause_timeout`）。只记**最近一个**会话。该会话再来 `prompt` / `working`（用户自己在 CC 里接着说了）就收起；其他会话的事件不影响
- 菜单：停下中仍是原来的“继续”（放行检查点），不变；没在停下时，在“停下”上面多一项：
  - **终端版**（hook 报的 `entry == "cli"` 且进程名 `claude.exe`）：“继续（发送“继续”） / Continue (send “Continue”) / 続ける（「続けて」を送信）”。点了在**单独的子进程**（`python -m shion.console_send`，QProcess，10 秒超时，同时只跑一个，发送中菜单项变灰）里做：只用 hook 报上来的 pid，先核对进程还在、名字是 claude.exe、创建时间一致 → `AttachConsole` → 读屏 → 逐字写 VK_PACKET + 回车 → `FreeConsole`。消息按存档语言：继续 / Continue / 続けて
  - **桌面端**（以及拿不准的情况，例如 hook 没报进程）：菜单项就叫“继续”，点了把“继续”（按语言）复制到剪贴板，诗音说“已经复制好啦，去 CC 里粘贴发送就行～”。不注入任何东西
- 读屏规则（`console_send.check_screen`，宁可不发）：
  - 最下面 25 行出现确认字样（Do you want / Yes / No, / Allow / allow / trust / 允许 / 信任 / Enter to confirm / Esc to cancel / Enter to select / proceed?）或带选中标记的编号选项（`❯ 1.` / `> 1.`）→ 不发（`dialog`）。回复里碰巧有这些字也不发；回复里不带标记的普通编号列表不算
  - 找不到“上下两条 `─` 横线夹住、以 `>` / `❯` 开头”的输入行 → 不发（`no_input`）
  - 输入行去掉提示符后必须是空的；唯一例外是 CC 的灰色占位提示 `Try "…"`，且控制台光标正好停在提示符后面（读屏分不出颜色，光标位置能区分：用户打过字，光标会跟在字后面）。否则 → 不发（`draft`）；输入不止一行也算 `draft`
- 结果台词：发出 → “发过去啦，接着干～”并收起这一项；`draft` → “输入框里还有没发出去的字，我就不动啦”；`dialog` → “屏幕上像是有确认框，我不替你按回车哦”；进程没了 / 找不到输入框 / 出错 → “没找到那个终端，去 CC 里说一声吧”。没发出去时这一项保留，可以再试（进程已经没了的除外）
- 实测（2.1.289，conhost 和 Windows Terminal）：空输入框能送达且前台窗口不变；有草稿、信任文件夹对话框、权限确认框都不发，草稿原样保留。限制：依赖 CC 现在的界面文字和输入方式，改版后要重新调整；读屏和写入之间用户恰好在打字，仍可能拼在一起

**hooks 配置**
- PermissionRequest、PreToolUse、PostToolUse 的 hook 超时要设得比上面的等待时间长（例如 PermissionRequest 180 秒、PreToolUse / PostToolUse 1900 秒），由 hook 脚本自己控制提前返回
- 实现后要在 CC 终端版和桌面端 Code 标签页里实测：授权请求能否被诗音接管、暂停时 CC 界面显示什么。结果记录到 progress.md

## 好感度系统（v0.4.1）

让好感度真正有作用：越相处越亲近。**不做好感下降**（几天不开电脑回来掉好感会让人有负罪感；冷落情绪交给已有的 neglect 临时状态表现）。

**数据驱动**：等级、阈值、名称、解锁内容写在 `assets/affection.json`（带 `schema_version`），代码里不写死，方便以后调平衡（内容包不能修改等级和阈值，只能让新内容带 `min_level`）。

**每日获取上限**（防止狂摸刷满；数值写进 json，以下为初始值）
- 摸头：每次 +1，每天最多 +20
- 喂零食：每次 +2，每天前 5 次有效（已实现，迁移到统一的每日上限逻辑）
- 预设对话：每个选项每天第一次 +1
- 首次启动问候、每天第一次打开：+2
- 每日计数按本地日期跨天清零；双击状态里可看“今天还能获得 X”
- 新系统启用后，“做得好”只加入工作反馈队列，不再额外加好感；配置失效时保留原先 +3 的行为。摸头达到好感上限仍可交互、统计次数；未吃完的零食不消耗次数。跨午夜喂食计入完成当天。
- 存档 v5 保存 `affection_level` 和 `affection_daily`（日期、摸头/零食/打开次数、当天已奖励的对话 id），保留旧 `snacks` 记录兼容已有存档；迁移时当天已有摸头和喂食计入额度。重启不重置额度，跨天不自动发打开奖励，需当天真的打开。

**等级**（初始阈值，用了几天后再调）

| 等级 | 累计好感 | 中 / 英 / 日 |
|---|---|---|
| 1 | 0 | 初识 / Acquainted / 初対面 |
| 2 | 50 | 熟悉 / Familiar / 顔なじみ |
| 3 | 200 | 亲近 / Close / 仲良し |
| 4 | 500 | 信赖 / Trusted / 信頼 |
| 5 | 1000 | 知音 / Kindred spirit / 知音 |

- 升级时：高优先级气泡说一句该等级专属的升级台词 + 一圈爱心（一次性，不受爱心限流）。当前等级写进存档，旧存档按已有好感直接算出等级，**不补播**升级台词
- 双击状态显示等级名和到下一级的进度
- 进度是“本级已获得 / 本级升至下一级所需”；满级显示“已满级”且仍可累计好感。“今天还能获得”只计当前已解锁的预设对话，解锁后立即更新。
- 迁移、重启或修复配置仅重新建立等级基线，不补播；一次奖励跨多级时仅播最终等级一次。升级气泡遵守静音，一圈 12 颗爱心独立于普通摸头粒子的间隔和总数限制。

**解锁**
- 对话选项、零食、自言自语台词都可以带 `min_level` 字段；未达到等级的不显示（不显示“未解锁”占位，保持惊喜感）
- 初始内容分配建议：“陪我一下”需要 2 级；新增 1～2 个高等级专属对话和零食；每个等级各有几句专属的自言自语，等级越高越亲近
- 5 级“知音”时，偶尔（低频）主动说“谢谢你一直陪着诗音”之类的话
- 本版内容：2 级“陪我一下”、3 级“听我说说”、4 级“分享巧克力”、5 级“以后也陪着我”；每级 3 句自言自语、各 2 句摸头和冷落回归台词，均有中英日原文。台词兼容旧字符串和 `{ "text": "…", "min_level": 3 }` 对象；菜单不显示锁定占位，选择入口也检查等级。
- 感谢台词只在原来的自言自语机会中抽取：初始概率 5%，两次至少间隔 1800 秒；这两个值写入 `affection.json`，不提高整体自言自语频率。

**反应随等级变化**（在现有概率基础上乘系数，系数写进 json）
- 戳她：等级越高，挡手、晕的概率越低，普通开心反应越多（例如 1 级 ×1.2，5 级 ×0.6，并保证概率总和合法）
- 五级系数初值为 1.2 / 1.0 / 0.85 / 0.7 / 0.6；同时乘挡手和晕概率，若总和超过 1 则按比例归一，余量为普通反应。
- 摸头台词：按等级选不同的台词池（低等级更别扭，高等级更撒娇）
- 被冷落回来时的台词也按等级区分

**测试要点**：跨天清零、各上限边界、等级计算与迁移、升级只触发一次、`min_level` 过滤、概率系数后的边界、json 缺失或损坏时回退到“只有计数、不分等级”的旧行为

**配置回退**：只在正式启动时加载配置；缺失、坏 JSON、不支持的版本或关键字段不合法则禁用等级与新每日奖励逻辑，使用旧摸头/零食/反馈计数、原始概率、通用台词和无等级过滤的菜单。保留已有等级/每日存档字段；修复配置并重启后按累计好感重新计算等级，不补播升级，并用当天交互统计补齐回退期间的摸头、喂食额度。

## 内容包（v0.5）

类似创意工坊：别人为**诗音**做好新内容发到 GitHub，其他人下载就能用。**角色永远只有诗音**：内容包只能给诗音增加说的话、零食和对话，不能替换角色、不能替换精灵图。

- **只允许数据，不允许代码**：内容包里只能有 json（以及零食图标这类小 PNG，见下）。加载时只解析允许的文件，忽略其他一切；解压时防止路径穿越（`../`）和超大文件（单个文件、总大小都设上限）
- **类型**（一个包可以包含多种）：
  - 台词包：给诗音新增台词，或新增一种语言的翻译（例如韩语）；可以给已有台词分类追加句子，**不能删除或覆盖**内置台词
  - 零食包：给“喂零食”菜单新增零食（可带 `min_level`、可选一张 ≤128×128 的小图标）
  - 对话包：给“对话”菜单新增预设选项和回应（可带 `min_level`、表情、动作，表情和动作只认现有白名单）
- **不支持**：替换或新增精灵图、修改好感等级和阈值、修改 hooks/遥控相关的任何行为
- **格式**：`manifest.json`（`id`、`name`、`version`、`author`、`license`、`types`、`min_shion_version`、各语言的名字和简介）+ 按类型分的子目录。诗音自带的台词、零食、对话也整理成同样的格式（内置、不能删除）
- **安装**：把 `.zip` 拖到诗音身上，或右键“导入内容包”；安装前显示名称、作者、许可证让用户确认。安装到 `%APPDATA%\Shion\packs\`
- **管理**：右键“内容包”：勾选启用/停用、查看详情、删除
- **给制作者**：模板仓库（带说明的空白包）；`tools/validate_pack.py` 检查 json 格式、字段、语言、白名单、图标尺寸并给出具体报错；README 里写“诗音的人设说明”（性格、口癖、称呼方式、不会说的话），帮助大家写出像她的台词
- 社区索引（`shion-packs` 仓库 + 应用内浏览）暂不做，等有人做了内容包再说

## 可测试性要求（重要）

CC 看不到屏幕，所以设计上必须让大部分东西能**不靠人眼**验证：

- **状态机是纯 Python**：`state.py` 不能 import Qt。时间通过参数传入（例如 `now: datetime`），不能在内部直接调用 `datetime.now()`，这样“2 小时后进入冷落”可以在测试里瞬间模拟。
- 测试用 `pytest`，放在 `tests/` 下。运行方式：`.venv\Scripts\python -m pytest -q`，只看失败的输出。
- **调试截图模式**：`python -m shion --snapshot out.png [--state happy] [--bubble "文字"]`，离屏渲染一帧存成 PNG 后退出。`--from-state idle --state happy --at 0.06` 可检查淡化中间帧；不传 `--from-state` 时直接显示目标状态。CC 需要检查画面时，生成截图再打开看，**只看截图，不要打开 assets 里的原始素材**。
- 截图动作参数互斥：`--turn --at 0/0.09/…/0.63` 检查八帧；`--face left|right` 检查侧身；`--cheek left|right|release` 检查捏脸与松手；`--tickle --at 0/0.2/0.4` 模拟持续挠痒；`--jump --at 0/0.15/0.24/0.44`、`--drag --at 0/0.11/0.22/0.33` 继续检查跳跃与拖动。可组合状态、三语气泡。移除旧的 --mirror / --walk。截图不创建 FPS 窗口，也不计实际绘制次数。
- 截图 `--panel permission|input [--panel-text 内容] [--panel-more N] [--panel-expand] [--lang ja]` 只画遥控面板。
- 截图 `--panel dialogue|snacks|eating [--lang zh|en|ja]` 检查对话首页、零食页或 happy 与碎屑效果；只查看此入口生成的截图，不打开精灵原图。
- **调试模式**：设置环境变量 `SHION_DEBUG=1` 时，冷落、睡眠的阈值缩短为秒级，并在控制台输出状态变化日志；诗音旁显示 FPS，每 0.5 秒按实际经过时间统计桌宠 paintEvent 次数。计数器独立刷新、透明点穿、不抢焦点，跟随移动与大小变化且限制在屏幕内，随桌宠隐藏/关闭。普通模式不创建该窗口。它表示 Qt 绘制频率，不代表显示器呈现频率；定时器、render_frame 和计数器自身绘制不计入。保留静止画面的重绘优化，静止时 FPS 较低是正常现象。
- 程序日志写进 `%APPDATA%\Shion\shion.log`，不要大量打印到终端。
