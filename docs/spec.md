# Shion（诗音）完整规格

> 中文名诗音，日文名詩音（しおん），英文名 Shion。她在台词里会用这个名字称呼自己。
> 非官方粉丝作品，与 Anthropic 无关。

## 技术栈

- Python 3.10+，GUI 用 **PySide6**
- 虚拟环境：`.venv`（`python -m venv .venv`，然后 `.venv\Scripts\pip install -r requirements.txt`）
- 依赖尽量少：`PySide6`、`pytest`；`numpy`、`scipy`、`pillow` 只给素材脚本用。hook 脚本**只能用标准库**。

## 窗口

- 无边框、背景透明、不在任务栏显示：`FramelessWindowHint | Tool | WindowDoesNotAcceptFocus`，加上 `WA_TranslucentBackground` 与 `WA_ShowWithoutActivating`。右键「置于最上层 / Always on top / 最前面に表示」默认开启，存档字段 `always_on_top` 缺失或类型错误时按开启处理（v5 兼容新增字段）。
- 置顶开关立即同步诗音、气泡、摸头/升级爱心、碎屑、睡眠 Z、暂停文字标签及调试 FPS；新建附属窗口也继承。关闭后可以被普通窗口盖住。Windows 切换 `WindowStaysOnTopHint` 后对原本可见的窗口重新 `show()`，保持几何位置、mask、其他 flags、点穿和不抢焦点属性，原本隐藏的窗口不因此出现。
- Windows 原生平台关闭「置于最上层」时，分别用 `SetWinEventHook` 监听 `EVENT_SYSTEM_FOREGROUND` 和 `EVENT_SYSTEM_MINIMIZEEND`（`WINEVENT_OUTOFCONTEXT`）跟随前台：当前前台窗口所属可执行文件名为 `Claude.exe`（大小写无关、多窗口/多 PID 均可）时，仅把本体及可见气泡、摸头/升级爱心、碎屑、睡眠 Z、暂停标签、FPS 按既有层级紧邻排到该窗口之上。查询其上方非本组的 Z 序邻居作为插入点；无普通邻居时使用 `HWND_TOP`，不借 topmost 邻居意外开启置顶。每次 `SetWindowPos` 带 `SWP_NOACTIVATE | SWP_NOMOVE | SWP_NOSIZE | SWP_NOOWNERZORDER`，不激活、不改变前台、不关联 Claude owner，Claude 最小化不连带隐藏诗音。回调只投递合并请求，延后查询 PID/程序名及重新确认当前前台；前台是 Claude 时即使仍最小化，也在约 150ms、500ms 各补查一次，同一轮重复事件合并、不延长已有补查，不轮询。每次操作前重新核对前台，非 Claude 时取消补查；无效/不可见/最小化的目标只跳过本次调整。诗音窗口若仍被 Qt 视为可见、却被 Win+D 等系统操作隐藏或最小化，则在跟随时用 `ShowWindow(SW_SHOWNOACTIVATE)` 恢复，再排 Z 序；显式隐藏/关闭的气泡及特效不恢复。启动/关闭置顶时检查一次，附属窗口显示或 HWND 重建时重查。开启置顶、退出、应用关闭及 dispose 取消补查并注销两个 hook；保留 ctypes 回调至全部注销成功。非 Windows/offscreen 跳过，API 失败记日志且不阻止运行。
- 授权请求切换到新的队首、计划提醒、有效完成提醒，以及「停下」后首次真正到达检查点时，整个提示前移一次；静音不影响前移，被诗音结束的一轮随后发来的 Stop 不触发。Windows 使用 `SetWindowPos(HWND_TOP, SWP_NOMOVE | SWP_NOSIZE | SWP_NOACTIVATE)`，不激活、不改变前台窗口、不重开置顶开关；授权/反馈/对话/关于面板排在本体和特效前面。
- 所有对话框（关于、反馈输入、对话选择、授权）始终独立置顶。按身体中心选择当前显示器，在可用区域内优先放右侧，放不下换左侧；两侧都不足时尝试上/下，并避免身体重叠。授权展开/折叠、对话换页后重新定位。用户主动打开的反馈输入与关于可以接收键盘；自动授权和对话选择原有不抢焦点规则不变。
- 程序版本唯一声明为 `shion.__version__ = "2.1.0"`，关于内容、QApplication 版本、exe 版本资源和 ZIP 文件名均从此读取；存档 schema 和内容 JSON schema 仍为各自协议版本。
- 默认显示高度 **200px**（图片按比例缩放，用平滑缩放）。右键菜单可以调成 160 / 200 / 260 / 320。
- 默认位置：主屏幕可用区域（`availableGeometry`，不含任务栏）的右下角，脚底贴着底边。
- 动作画布按原比例缩放至指定高度，宽度随动作变化，脚底中心保持不动；贴边时优先把本体夹进屏内。交叉淡化按各图自己的宽度、脚底中心对齐，不拉伸；过渡结束才收窄画布。绘制、遮罩、气泡/面板跟随共用当前本体尺寸。
- 透明像素要能**点击穿透**。Windows 的分层窗口一般会自动穿透，务必实测确认。如果不行，用 `setMask` 根据当前帧的 alpha 生成遮罩。
- 只允许运行一个实例：用 `QLocalServer`/`QLocalSocket` 检测，第二个实例启动后直接退出。

- 捏脸/挠痒不增加好感度、摸头次数或工作反馈，清空普通连戳累计；动作层覆盖当前表情，结束后固定/自动状态保留。被拎起或进入其他手势会取消挠痒，不补播喘气台词；自然停手只说一次。

## 程序动画（animator.py）

- **呼吸**：idle、neglect1 状态下，纵向缩放在 1.000 和 1.025 之间正弦变化，周期 3 秒；working 独立使用 1.000～1.008、4 秒周期的轻呼吸。其余 calm 表情沿用 1.000～1.012、3 秒周期，道具帧不叠加程序呼吸。全部以脚底中心为锚点。
- **工作点头**：working 每 3～5 秒随机一次，sin² 曲线在 0.4 秒内压缩/回正；相对呼吸额外 sy 最多压缩 1.5%，同时前倾 1°，脚底中心不变。独立随机流不改变眨眼或道具调度；工作默认 calm 与安静档仍保留点头。按住、拖动/下落和动作层期间取消；恢复后重新等待，掉帧不补播，离开 working 清空待触发事件。常量集中在 animator.py。
- **冷落慢摇**：仅 neglect2 叠加 ±1.2°、3.5 秒周期的正弦摇晃；固定/calm、安静档、按住、拖动/下落或动作层期间关闭，沿用脚底中心与姿态淡化。
- **睡眠 Z**：sleep / bed 从各自头部右上锚点立即冒一枚，此后每 0.9 秒一枚，最多 3 枚；寿命 2.4 秒，向右上匀速漂移总计 40 逻辑像素（保持相邻粒子间距），0.5→1 倍放大、±8°/1.2 秒周期摆动；最后 1/3 寿命线性淡出。醒来或显示动作时停止发射，从当前透明度立即开始 0.15 秒淡出；重入不复活旧粒子。四档高度 160/200/260/320 按 200 高基准缩放位置偏移、距离、尺寸和窗口，bed 缺图回退时使用 sleep 锚点。透明 Tool 窗口完全点穿、不接键盘、不激活，不并入身体 mask；跟随移动/大小与置顶开关，隐藏/关闭清理。由桌宠真实帧时钟驱动、掉帧不补发；全部参数集中在 effects.py 的 Z_* 常量。
- **待机慢摇摆与换重心**：仅 idle（含其眨眼）叠加 ±1.5°、4.5 秒周期的正弦摇摆，恢复时用 0.3 秒平滑进入。普通档每 8～15 秒、活泼档每 5～10 秒随机一次换重心，持续 0.6 秒：约 2% 下蹲后 0.6% 轻回弹，或随机向左/右歪 3° 再回正。歪身平滑接管慢摇摆，最大角度保持 3°。时间/幅度/频率集中在 animator.py 常量中，独立随机流不影响眨眼/道具时间线；按真实时间推进，过期微动作不补播，不改变状态、好感或交互/睡眠计时。
- 新增待机姿态在拖动、下落、按住鼠标、跳跃（含缺图回退）、捏脸/挠痒、道具动作、非 idle 状态、calm、固定表情或安静档期间取消；恢复后重新等待，摇摆从零平滑进入。安静档仍保留适用的呼吸/眨眼。旧待机小跳等调度保持原规则。
- **眨眼**：idle 状态下每隔 3～6 秒（随机）切到 blink 120ms；有 15% 的概率连续眨两次。
- 所有缩放、倾斜都以**脚底中心**为锚点，避免人物飘起来。
- 动画计时器用 `Qt.PreciseTimer`；桌宠、气泡、粒子按 `time.perf_counter()` 的实际经过时间计算，掉帧后直接到达对应时刻；下落使用重力位置解析式，不截断经过时间。
- 切换精灵使用约 120ms 的 ease-out 交叉淡化，附带约 3% 的压扁和轻微回弹；快速切换时从当前混合画面接续，缩放、角度也从当前姿态缓动，脚底锚点保持固定。眨眼的淡化不附加压扁。
- 动作序列在显示层覆盖底层表情，序列内部直接按经过时间取帧，不对每一帧做状态淡化。结束或中断后恢复当前底层状态；绘制与遮罩使用同一动作帧和位移，掉帧不拖慢动作。落地回弹以预定落地时刻计时。
- **抱胸待机与动作衔接**：仅底层为 idle（含其眨眼）时，进入有效跳跃帧、捏脸或挠痒的动作层，以及动作结束/中断返回 idle 时，按透明度线性混合约 0.10 秒；时长集中在 `pet_window.ACTION_FADE_SECONDS`。不增加压扁或延长动作，动作内部仍直接切帧；自然结束从预定结束时刻的末帧开始淡出，掉帧不补播。快速中断/连续触发从当前混合接续，淡化结束移除旧层。各层按原宽和脚底中心对齐，mask 取所有可见层的完整轮廓并集，并按既有规则扩边；仅透明度变化时复用轮廓。表情之间的切换、拖动/下落、眨眼保持原来的行为，不增加这层淡化；底层切离 idle 或开始拖动/下落即清掉它，无有效动作帧的旧跳跃回退也不增加淡化。
- 爱心/碎屑粒子位移使用三次 ease-out，睡眠 Z 匀速漂移；拖动倾斜使用指数 ease-out，压扁使用先压缩后回弹的平滑曲线；鼠标拖动位置仍直接跟随用户输入，下落保持非线性重力加速。
- 待机动作由独立行为调度器控制。Claude 工作中、固定表情、睡眠和安静档关闭原待机摆动，保留适用的呼吸/眨眼及上述工作点头、睡眠 Z；独立 blink 图仅用于 idle。绘制和遮罩共用当前原始动作帧及脚底锚点，不创建镜像缓存。所有序列按真实经过时间取帧，掉帧不拖长动作的持续时间。
- 遮罩按 1° / 0.01 缩放 / 1px 升空位移量化缓存，淡化时取图片可见区域并集；仅透明度变化时复用遮罩。最多缓存 64 项，LRU 逐项淘汰，不再整批清空。每次未命中只绘制一遍，再平移合并区域扩边（4 逻辑像素）；画面本身保留 0.01° / 0.001 缩放精度，不随遮罩量化跳动。

## 状态机（state.py）

优先级从高到低（高优先级的临时状态结束后，回到底层状态）：

1. **drag**：正在被拖动
2. **固定表情 / 手动表情**：固定无期限；未固定的手动表情 5 秒
3. **临时反应**（有持续时间）：happy、stop、dizzy、done（3 秒）、proud（3 秒）
4. **working**：按会话（session_id）计算，任意一个会话在工作就显示。会话从 UserPromptSubmit / PreToolUse 开始算工作中；PreToolUse 之后、对应的 PostToolUse / PostToolUseFailure（按 tool_use_id 配对）之前一直保持（单个工具最长 30 分钟）；没有在执行的工具时，距最近事件 5 分钟（调试模式 60 秒）才退出。这个会话 Stop / plan_ready / 被中断或停太久结束 / Notification `idle_prompt` 时立刻退出；别的会话还在工作时，done 3 秒之后回到 working。plan_ready 只提醒看计划，不计为完成任务、不触发 done 或完成后的定时催促
5. **sleep**：本地时间 0:30～6:30，或者 15 分钟没有实际鼠标操作、也没有 Claude 事件。实际交互按原规则唤醒，唤醒时说一句起床台词；悬停与浏览/取消右键菜单不唤醒、不延后入睡
6. **待机短暂表情**：happy / idle 2 秒
7. **底层状态**：根据冷落值决定
   - 距离上次“被理会”（摸头、点击、或任意 Claude 事件）**< 30 分钟** → idle
   - **30 分钟～2 小时** → neglect1
   - **> 2 小时** → neglect2
   - 从 neglect2 回到 idle 时，说一句特别的台词（例：`> ……你终于回来了。`）
   - 阈值写在配置里，方便调整

好感度：整数，只增不减（摸头 +1，做得好 +3，吃完零食 +2），目前只在双击状态里显示，后续可以用来解锁台词。预设对话不增加好感度或摸头统计。

状态变化后延迟 2 秒写盘（防抖），退出时立即写。写文件时先写临时文件再替换，防止写到一半损坏。
旧存档没有 `schema_version` 时按 v1 处理：因无法分辨待表扬来自摸头还是菜单，升级丢弃旧 `pending_praise`，其余数据保留；v2 的 `pending_praise`（都来自菜单）迁移成反馈队列里等量的“做得好”（最多 5 条）；v3 起不再写 `pending_praise`。`feedback_queue` 最多 5 条，每条 `kind` 为 `good`/`bad`，`text` 单行最多 200 字；`remote` 的秒数会被限制在安全范围内（暂停 60～1880，授权 10～170），hook 脚本直接读它。缺失/非法的表情和活跃度恢复默认值。

v4 新增独立 `snacks` 统计：本地日期和当天成功吃完的次数（0～5），缺失/非法次数默认 0，跨日清零；重启不清零。旧档保留其他数据。正在吃东西和菜单触发的睡眠不持久化。

v5 可选字段 `time_speech`：`{"date": "2026-10-21", "spoken": ["time_noon"]}`，独立记录当天已实际显示的时段台词类别。旧档缺失或字段非法时默认空记录，仅保留五个合法类别、去重；按本地自然日清零，重启及切换语言不清零。使用现有防抖/退出写盘机制，不改变好感度或每日奖励。

`connection_prompt` 是兼容 v5 的可选字段：`pending`（尚未选择）、`connect`（已选连接）、`later`（以后再说）、`skipped`（旧存档跳过）。缺失/非法值先视为未初始化；全新首次启动初始化为 pending，已有存档初始化为 skipped。点击后立即写盘，即使连接失败也不再自动询问；尚未选择就退出则保留 pending，下次启动问候结束后继续提示。

`release_to_taskbar` 是可选布尔字段，缺失/非法值默认 false。窗口 x 按普通画布换算，y 保留实际悬空位置；重启、改大小或任务栏变化只夹边，不强制贴底。旧档只有 x 时仍按原规则贴底；原屏已移除则回默认位置。床/桌状态不持久化。

## 对话气泡（bubble.py）

- 独立的无边框小窗口，置顶与桌宠开关同步，跟随在桌宠头顶上方；如果靠近屏幕边缘，自动翻到另一侧。
- **终端风格**：背景 `#0A0A0A`，1px 橙色 `#F58236` 边框，圆角 4px，米白色文字，等宽字体（优先 `Cascadia Mono`，回退到 `Consolas`），每行开头加 `> `。
- 打字机效果：每 30ms 出一个字，全部显示完后停留 4 秒再淡出（0.3 秒）。
- 台词统一经控制器仲裁：高优先级（完成提醒、计划写好提醒、出错、催促、等待确认和授权请求）随时打断；中优先级（问候、唤醒/回归、菜单反馈、双击状态查询）只能打断低优先级；低优先级（摸头、戳、拖、自言自语、工作过程提示）不能打断中/高。当前气泡自然消失后不再阻挡。
- 低优先级互相替换时，当前气泡须已出现至少 2.5 秒（从气泡开始出现计时，不从打字完成计时），且同一触发类别已实际说出的台词至少间隔 4 秒；戳导致的普通/挡手/晕共用戳冷却，拖动及其落地晃晕共用拖冷却。被拦截的台词丢弃，不补播，不消耗随机台词选择。
- 三语原生提供 cheek_pull / cheek_release / tickle / tickle_end，各至少三句，保持傲娇语气。cheek_pull、tickle 属低优先级；松手生气与停止后的喘气属中优先级，可接替刚发生的互动台词；静音及中/高优先级工作消息仍照常仲裁，不排队补播。
- 相邻摸头间隔 ≤1 秒算同一过程：开始尝试说一句，连续持续超过 6 秒再尝试一句，同一过程最多两句；仍受低优先级规则限制。每次摸头的爱心、表情、好感度及统计照常。相关时间都在 `speech.py`。
- 台词从当前语言的 json 随机抽取，同一类台词不要连续重复。静音时不弹气泡。
- 气泡字体：首选等宽字体不变，后面追加当前语言 `meta.font_fallback` 里已安装的字体（日文、中文字符走它）。

### 多语言（lines.py）

- 语言文件 `assets/lines/<代码>.json`，格式：`meta`（`name` 是该语言自己的名字，显示在菜单里；`font_fallback` 是字体备选列表）、`lines`（台词类别 → 台词数组）、`ui`（界面文字，`{xxx}` 是占位符，如 `{version}`、`{span}`、`{port}`）。
- **语言列表自动扫描**该目录下所有能解析的 `*.json`（坏文件跳过），中文排第一，其余按代码排序。新增语言只需放一个 json，不用改代码。
- **回退**：缺的台词类别、缺的界面文字都回退到中文（`zh.json` 必须完整）；`ui()` 在占位符对不上时不抛异常；语言文件不存在就用中文。
- **首次启动**（存档里没有 `language`）跟随系统语言（`QLocale`）：`zh*` → 中文，`ja*` → 日文，其他 → 英文；结果写入存档，之后固定。
- **启动台词**：没有存档文件时说当前语言的 `intro`；非首次普通启动一律使用 `startup`，不再随机重复自我介绍。hook 仅对子进程设置 `SHION_LAUNCHED_BY_HOOK=1`，非首次被 hook 拉起时不说普通启动台词，交给 `session_start` 的 `greeting` 问候；遵守静音设置。
- 右键菜单「语言」子菜单列出扫描到的语言（单选），选择后立即生效（菜单、双击状态、之后的台词、气泡字体），保存到存档，正在显示的气泡收起。

### 时段台词与等级混合抽样

- 内置五类 `time_morning / time_noon / time_evening / time_late / time_dawn`，每类三句，三语原生提供。本地时间分别为 **[05:00,10:00)、[11:30,13:30)、[17:30,19:30)、[23:00,次日02:00)、[02:00,05:00)**；边界集中在 `state.py` 的 `TIME_SPEECH_PERIODS`，空档不说、不补播过期时段。
- 每个时段每天最多实际显示一次。在启动、实际交互处理完成后或原有闲聊机会中尝试；原介绍、启动、唤醒、交互回应和升级提醒优先，时段台词属于低优先级。普通工作事件、悬停、仅浏览/取消菜单不增加触发机会。双击等待状态回应后再尝试。
- 工作中（按真实会话，不能被临时/固定表情遮住）、静音、睡眠或暂停时不说；现有中高优先级气泡、低优先级最短可见时间及类别冷却照常阻挡。被挡不抽取、不消耗时段资格；成功显示后才写 `time_speech`。阻挡解除不逐 tick 补说，只在同一时段内的后续实际交互或闲聊机会重试；闲聊机会已说时段台词就不再说普通闲聊。
- 按本地自然日计数，23 点和次日 0 点的 late 属于不同日期，可各说一次。首次介绍及普通 startup 保留优先级；hook 启动仍不说普通 startup，但同样可以尝试符合条件的时段台词。
- `pat / neglect_return / idle_talk` 使用 `Lines.pick_for_level()`：当前等级池占 **60%**，所有更低等级池及通用池平分余下 **40%**，先选池再在池内等概率选句。权重由 `lines.py` 的 `CURRENT_LEVEL_WEIGHT` 集中控制；未解锁台词不参与，空池剔除后归一，只有通用池时全部使用通用池。
- 三种混合抽样各按基础类别共享上次台词记录；先排除上次句子，再按剩余池归一抽取，只有一句可用时允许重复。满级感谢保留原概率与冷却，未命中时用混合池；等级配置失效时仍用通用池。

## 本地通信协议（server.py）

- 监听 **`127.0.0.1:47613`**，只绑定本机。用标准库 `http.server` 在后台线程运行，通过 Qt 信号把事件转发给 GUI 线程，**不能在后台线程里直接操作界面**。
- `POST /event`，请求体为 `{"type": "...", "detail": "可选"}`

| type | 来源 | 桌宠行为 |
|---|---|---|
| `session_start` | SessionStart hook | 说一句问候，刷新“被理会”时间 |
| `prompt` | UserPromptSubmit hook | 刷新“被理会”时间 |
| `working` | PreToolUse hook | 进入 working（已经在 working 时不重复说话），记下在执行的工具 |
| `tool_done` | PostToolUse hook（放行后）；PostToolUseFailure 的 Esc 中断 | 工具执行完，不说话 |
| `stop` | Stop hook | 退出 working → 播放 done 3 秒 + claude_done 台词，claude_tasks +1。**例外**：这个会话的这一轮刚被诗音结束（立即中断、检查点拿到 stop 即 `work_stopped`、`pause_timeout`）时，紧接着的那次 Stop 按 work_stopped 处理：不加 claude_tasks、不显示 done、不说完成台词、不催、最近活动不记“做完了”，菜单仍提供“继续”；该会话再来 `prompt` 时这个标记作废 |
| `plan_ready` | ExitPlanMode 的 PermissionRequest hook | 高优先级气泡“计划写好啦，去看看吧～”并跳一下；退出 working，不弹授权面板、不计完成任务 |
| `notification` | Notification hook | 气泡提示“有事情等你确认哦”（只有终端版会触发）。`detail` 是官方字段 `notification_type`；为 `idle_prompt`（CC 回复完约 60 秒用户没输入）时，清掉这个会话的“工具在执行中”和 working（在提问框上按 Esc 等情况 CC 不发 PostToolUse / Stop），并收起这个会话还挂着的授权面板 |
| `react` | 预留（目前没有调用方） | `detail` 是表情名，临时切换到该表情 3 秒 |

- `POST /feedback/take {"session": 可选}` → 返回 `{"text": "…"}`：取走反馈（带 session：取给这个会话的和无归属的；不带或不合法：只取无归属的，旧 hook 兼容），按存档语言合成要注入的文字（没有则为空串；`inject_praise` 为 false 时仍清空但返回空串）。读取和清空是同一个原子操作
- 会话字段（`/event` 可选，`server.parse_meta` 校验，不对就 400）：`session`（stdin 的 session_id）、`tool_id`（tool_use_id），以及 prompt / PreToolUse 附带的 `proc`：`{"pid", "created"(FILETIME), "name"(只认 claude.exe/node.exe/bun.exe), "entry"(CLAUDE_CODE_ENTRYPOINT), "hooks"(hook 自己到 CC 之间的 pid，最多 8 个)}`。带会话字段时回调为 `on_event(type, detail, meta)`，否则仍是两参数。另有可选 `project`：hook 取 stdin `cwd` 的最后一段（只发文件夹名，不发完整路径）；服务端 `clean_project` 校验：必须是字符串，去掉控制字符（Unicode Cc）和格式字符（Cf，含 RTL 覆盖），去首尾空白，含 `/` `\`、为空或超过 64 字时**只丢掉这个字段，事件照常处理**（不 400）。只用于工作遥控菜单和检查点面板的显示名
- `POST /pause/wait {"wait": 秒, "session": 可选}` → `{"paused": true|false, "stop": true|false}`：检查点长轮询。没在停下就立即返回；停下等待中最多等 `wait` 秒（上限 30），用户点“继续”立即返回 `paused: false`；等满上限（`pause_timeout`）时**此刻正在等的所有请求**都返回 `stop: true`（之后到达的请求不受影响，不留残余状态）；这个 `session` 被“立即中断”过时立即返回 `stop: true`（只生效一次，正在等的也会被唤醒）。拿到 stop 时服务线程向界面发内部事件 `work_stopped`（带 session）。hub 记录正在等的请求数，两段长轮询之间 2 秒内仍算“在等”。**没有任何接口能让 HTTP 调用方开始停下、结束这一轮或请求中断**，`/event` 里的 `work_stopped` 一律 400；`prompt` 事件到达时服务线程直接解除等待；`stop` 事件在没有 hook 正在等时作废没用上的停下；`prompt` / `stop` 带 session 时作废该会话没用上的中断标记
- `POST /permission/open {"tool", "detail", "session"?, "key"?}` → `{"id"}`（请求体上限放宽到 64 KB；排队上限 20，满了返回 503；`session` ≤128 字，`key` 为 ≤64 位小写十六进制，不对就 400）；`POST /permission/settle {"session", "key"?}` → `{"settled": N}`：撤掉这个会话（给了 key 就只撤指纹相同的）还在等的请求，hook 之后拿到 `gone`、不给决定；`/event` 的 `prompt` / `stop` / `notification`（`idle_prompt`）带 session 时同样撤掉该会话全部未决请求；`POST /permission/wait {"id", "wait"}` → `{"id", "status"}`，`status` 是 `pending`/`allow`/`deny`/`gone`，`allow`/`deny` 只能取一次；`POST /permission/withdraw {"id"}` 撤回。**没有任何接口、任何字段能写入 allow/deny**，决定只来自诗音界面上的按钮（有测试往所有接口和事件类型里塞各种“同意”字段，请求始终保持 pending；另有源码级测试保证只有 controller 的按钮回调会写入决定）
- `type = pause_timeout`（hook 等满上限后发来）：只在停下等待中有效，界面放掉其他并行等待的 hook（也返回 stop），提醒一次“停太久了，这一轮先结束啦，在 CC 里说一声就能接着做”（不常驻）
- `GET /health` → `{"ok": true}`
- 安全：带 `Origin` 头的请求（来自网页）和 `Host` 不是 `127.0.0.1` / `localhost` 的请求一律返回 403，不触发任何回调；读请求体有 5 秒超时。hook 脚本是普通 HTTP 客户端，不受影响。
- **令牌**（v2.0 发布前安全修复，`shion/loopback.py`）：所有路由（含 `/health`）都要带 `Authorization: Bearer <令牌>`，用 `hmac.compare_digest` 比对，不对就 403、不读请求体、不触发回调。令牌是每次启动新生成的 64 位小写十六进制（`secrets.token_hex(32)`），存在数据目录（`%APPDATA%\Shion`，`SHION_DATA_DIR` 可覆盖）的 `claude-link.json`：`{"token": "…", "pid": 诗音进程号, "created": 诗音进程创建时间(FILETIME)}`，继承数据目录的用户权限，同目录临时文件 + `os.replace` 原子写入。只检查**最后两层**（数据目录本身、令牌文件本身）是不是重解析点，上级目录不查（别的账户改不了上级目录；用 junction 搬过家的用户目录照常可用）。启动顺序（`server.start_linked`，返回 `ok` / `port_busy` / `token_failed`）：先删旧令牌文件 → 绑定 47613 → **绑定成功才写新令牌**；端口被占时不写；令牌写不进去时服务照常运行但 hook 连不上，界面说 `ui.link_token_failed`（端口被占仍说 `ui.port_busy`）。正常退出时先删令牌再停服务（`server.stop_linked`）。hook 用 `loopback.read_link`：令牌格式对、**而且写它的诗音进程还在运行**（`winproc.process_running`：创建时间对得上、退出码是 STILL_ACTIVE；只看创建时间不够，进程退出后别的进程握着句柄时内核对象还在）才算数，否则一个请求都不发——没有令牌（端口被占）或诗音崩溃留下的旧令牌，都不会把命令发给占着端口的进程，也不会采纳它的“同意”或反馈。hook 每个进程读一次令牌（读不到时每次请求前再试；SessionStart 拉起诗音后的 `/health` 探测会重新读；收到 403 时重读一次，令牌换了才用新令牌重试一次）。
- **独占绑定**：47613 和 ChatGPT 观察端 47614 都不设 `SO_REUSEADDR`，Windows 上设 `SO_EXCLUSIVEADDRUSE`，诗音绑上以后别的 socket（即使设了 `SO_REUSEADDR`）不能再绑同一端口抢连接。
- **观察端口隔离**（R5）：`chatgpt-observer.json` 只在**首次新建**时才读环境变量 `SHION_OBSERVER_PORT`（1024～65535 的整数，否则用 47614）；已有文件不受影响。只给打包烟测 / 测试隔离用，避免占用正在使用的诗音的 47614。

## Claude Code hooks（v0.2）

`hooks/shion_hook.py <事件名>`：

- 只用标准库（`urllib.request`），**超时 0.5 秒**。桌宠没运行或请求失败时**静默退出、返回码为 0**，绝不能影响 Claude Code 的正常使用。读不到数据目录里的令牌（见「本地通信协议」）时按诗音没开处理，一个请求都不发。
- `UserPromptSubmit` 附带的 `prompt_head` 只在**存档读成功且 `privacy_mode` 不是 true** 时发送；存档不存在或损坏时拿不准是不是隐私模式，不发。
- 从 stdin 读取 hook 输入的 JSON（可以不用，但必须读完）。
- `UserPromptSubmit`：先发送 `prompt` 事件，再调用 `/feedback/take`；返回的文字非空就原样打印到 stdout（`[诗音] 用户觉得你刚才做得很好。` 等，按存档语言使用中/英/日；多次“做得好”合成一句，不写次数；摸头不产生反馈）
- 所有事件都带 `session`（和 `tool_id`）；UserPromptSubmit / PreToolUse 另带 `proc`：用 Toolhelp 快照从 hook 自己沿父进程链往上找，有 `CLAUDE_PID` 环境变量时必须在链上找到它（否则不带），没有时取最近的 claude/node/bun 祖先；进程表工具在 `shion/winproc.py`（只用标准库）
- `PostToolUse` / `PostToolUseFailure` 一进来（检查点等待之前）先调 `/permission/settle`，带 session 和 `key = sha256(json.dumps([tool_name, tool_input], sort_keys=True))` 前 32 位：工具已经跑过，说明它的授权在 CC 里答过了
- `PermissionRequest`：`/permission/open` 带 session 和同样算法的 key（官方：PermissionRequest 没有 tool_use_id，只能按工具名 + 参数配对）
- `Notification`：detail 发 `notification_type`（截短 40 字），不转发 message
- `PostToolUseFailure`：发 `tool_error`；`is_interrupt`（用户在 CC 里按 Esc）时改发 `tool_done`。**不是检查点**：实测（2.1.289）CC 不理会它返回的 `continue: false`
- `PostToolUse`：**检查点**（同 PreToolUse 的 `/pause/wait` 逻辑）。放行后先发 `tool_done`，再调用 `/feedback/take`，非空则输出 `hookSpecificOutput.additionalContext`（Claude 工作中即可收到反馈）。被立即中断或等满上限时输出 `{"continue": false, "stopReason": …}`，不取反馈（留给下一次 UserPromptSubmit）
- `PreToolUse`：**检查点**。先问 `/pause/wait`；停下等待中就按 25 秒一段一直等，直到“继续”或 `prompt` 解除；诗音没开、连不上、返回内容不对一律放行（`stop`/`paused` 必须恰好是 `true` 才算数）。被立即中断或等满上限时输出 `{"continue": false, "stopReason": …}` 并附带 `permissionDecision: deny`（保证这次工具不执行），不发 `working`；等满上限（`remote.pause_timeout`，默认 30 分钟）同样处理并发 `pause_timeout`
- `stopReason` 按存档语言取 `ui.hook_stop`（默认“用户通过诗音让这一轮工作停下，请等待用户指示”）；等满上限取 `ui.hook_stop_timeout`（默认“用户很久没有回应，这一轮先结束，请等待用户指示”）。官方文档：`continue: false` 让 Claude 在 hook 运行后完全停止处理，优先于任何事件专属的决定字段；`stopReason` 显示给用户并留在对话里；对 PreToolUse 和 PostToolUse 都有效
- `SessionStart`：如果 `/health` 不通，就启动桌宠（`.venv\Scripts\pythonw.exe -m shion`，脱离父进程，不弹出控制台窗口），然后发送 `session_start` 事件。
- `Stop`：只发送 `{"type":"stop"}`，不读取/转发 `last_assistant_message`，不打开 `transcript_path`。只说当前语言的完成提醒。（token 统计由主程序另行只读扫描，见「V2.1 诗音周报与体力」）
- 其他事件（`PreToolUse` 发 `working`）只负责转发。
- 配置写进**用户级** `~/.claude/settings.json` 的 `hooks` 字段，这样终端和桌面端的 Code 标签页都会加载。写之前先备份原文件，**合并而不是覆盖**用户已有的配置。另外写一个 `tools/install_hooks.py`（安装）和 `tools/uninstall_hooks.py`（卸载）。
- **转圈文字**：PreToolUse / PostToolUse 两个检查点条目带官方通用字段 `statusMessage`（“hook 运行时显示的自定义转圈文字”），取 `ui.hook_status_waiting`：中“诗音在看着～（一直停在这里就是暂停了，右键诗音点继续）”/ 英 / 日，写成平时一闪而过不奇怪、停下时一直显示也看得懂。其他事件不加。文字在**安装时**按诗音存档语言写入（`--lang zh|en|ja` 可指定）；在诗音里换语言后要重跑一次 `install_hooks.py` 才会跟着变。**转圈文字只在终端版显示**，桌面端 Code 标签页不显示 hook 的 statusMessage（已知限制，用户验收 2026-10-21，不修），桌面端靠暂停标签

## 状态感知（v0.2.1）

让诗音知道 Claude Code 正在干什么，当好状态窗口，也是 v0.3 遥控功能的“眼睛”。全部基于 hooks，只读，不打扰工作。

- **完成提醒**：Stop 只提示去看结果，中文如“做完啦！去看看结果吧～”；英文如“All done! Take a look at the results~”；日文如“終わったよ！結果を見てみてね～”。三语均有原生台词，不显示回复第一句；旧 hook 发来的 stop detail 也不显示、不记录到最近活动或控制器日志。最近活动只显示“做完了”。done 表情、任务计数和定时催促保留
- **计划提醒**：ExitPlanMode 的 PermissionRequest 仅发送无 detail 的 `plan_ready` 事件，计划正文不发送。三语分别是“计划写好啦，去看看吧～” / “The plan's ready! Take a look~” / “計画ができたよ、見てみてね～”。高优先级可打断已有气泡，同时复用菜单原地跳跃一次（静音只抑制气泡，仍跳；拖动/下落时沿用跳跃的保护，不强行中断）。不登记授权、不轮询、不输出 allow/deny，确认由 CC 自己处理
- **显示正在干什么**：PreToolUse 时根据工具名和参数生成简短描述，例如“在读 state.py……”“在跑命令……”“在改 bubble.py……”。同一个描述 3 秒内不重复弹出
- **出错反应**：工具执行失败时（PostToolUse 结果里带错误，或官方提供的失败事件），切到 dizzy 2 秒，说一句“呜……出错了”
- **催你回来**：Claude 停下后，如果 5 分钟（可配置）没有新的 UserPromptSubmit，诗音跳一下提醒；最多提醒 2 次
- **最近活动记录**：内存里保留最近 20 条事件（时间、类型、简短描述），双击状态里可以看最近 5 条；不写入存档
- **隐私开关**（右键菜单）：“只显示状态，不显示内容”。打开后不显示文件名、命令；回复内容无论开关状态都不显示

## Claude Code 遥控（v0.3）

诗音成为 Claude Code 的遥控器。**只用官方 hooks 机制，不模拟按键，不往对话里发消息。**唯一的例外是下面「这一轮结束后的继续」：终端版 CC 在用户点了菜单后，往它的控制台写一句“继续”（不切前台、不用 SendInput）。 工作遥控相关的界面文字里不出现“Claude”，统一叫“工作”。

右键菜单新增“工作遥控”子菜单；需要用户决定时，诗音会主动弹出带按钮的气泡。

| 操作 | 实现 | 行为 |
|---|---|---|
| **同意 / 否决** | **PermissionRequest hook**：返回 `hookSpecificOutput.decision.behavior` 为 `allow` / `deny`（字段按官方文档确认）。hook 脚本向本地服务器长轮询，等待用户在诗音上的选择 | 气泡显示要执行的命令或要改的文件（完整显示，过长时可展开）和两个大按钮。**ExitPlanMode 例外，只提醒，计划确认由 CC 自己处理** |
| **做得好 / 有问题** | 放进**反馈队列**；送达方式见下 | “有问题”可以附一句话（单行输入框，可留空） |
| **停下 / 继续**（子菜单第一项） | **PreToolUse 和 PostToolUse 两个检查点**：hook 长轮询原地等待；“继续”放行，停太久返回 `continue: false` + `stopReason` | 见下面「停下规则」 |
| **立即中断**（第二项） | 结束 CC 进程下正在跑的工具子进程树 + 一次性中断标记，下一个检查点返回 `continue: false` | 见下面「立即中断」 |
| **继续（这一轮已结束）** | 终端版：子进程 AttachConsole + WriteConsoleInputW 写“继续”+回车；桌面端：复制到剪贴板 | 见下面「这一轮结束后的继续」 |

**同意 / 否决的安全规则**
- 决定**只能由用户在诗音界面上亲手点击产生**。本地 HTTP 服务**不提供**任何“设置决定”的接口，hook 只能“等待结果”
- 默认等待 **120 秒**（可配置）。超时后 hook 不给决定，CC 照常弹出自己的授权框。**任何情况下都不能默认同意**
- **CC 自己的授权框会同时显示**（实测 2.1.289：hook 等待期间 CC 就显示自己的框，不能关掉），两边哪边先答都可以；在 CC 里答了以后诗音面板会自动收起（见下面「排队」）
- 诗音没在运行、连不上服务器时，hook 立刻退出、不给决定，交回 CC 自己处理
- ExitPlanMode 无论有无计划、计划多长，一律不登记请求、不给决定；只尝试发送 `plan_ready`，发送失败也静默退出
- 同一时间可能有多个授权请求（例如子代理并行）：按顺序排队，一次只显示一个，显示“还有 N 个”
- 否决时附带理由“用户通过诗音否决了这个操作”
- 内容超过 12000 字（面板放不下、用户看不全）时，hook 不登记请求、不给决定，交回 CC 自己的授权框
- 威胁模型：防网页（Origin/Host 检查）、“hook 出错/超时/诗音没开”，以及**本机其他账户或读不到当前用户数据目录的进程**（v2.0 起本机 HTTP 有令牌认证，见「本地通信协议」：它们不能冒充 hook 解除暂停、取走反馈、撤掉授权请求；抢先占着 47613 时诗音不写令牌，诗音崩溃留下的旧令牌也因为写它的进程已不在而不被 hook 采用，hook 都不会去连。命名管道名是整台机器共用的，别的账户在诗音没开时能冒充管道，所以 hook 不靠管道判断身份，只靠令牌和进程核对）。**仍不防以当前用户身份运行的恶意进程**：它读得到令牌文件、能改 `~/.claude/settings.json`，本来就能控制 CC

**反馈队列（做得好 / 有问题）**
- 内容示例：`[诗音] 用户觉得你刚才做得很好。` / `[诗音] 用户认为刚才的改动有问题：<用户输入的话>。请重新检查。` 不加“请回复”之类的话
- 送达（只用附加上下文，不产生聊天消息）：
  - Claude 正在工作：下一次 **PostToolUse** 的 `additionalContext`（官方说明：放在工具结果旁边，Claude 下一轮会读到，不作为聊天消息显示）
  - Claude 空闲：下一次 **UserPromptSubmit** 时附加
- 多条合并成一次送达；队列最多 5 条；送达后诗音说一句“已经转告啦”
- 点的时候诗音说的话：工作中说“收到！马上转告～”/“收到！这就去转告～”（`praise_menu_working` / `feedback_bad_working`，三语）；空闲时保持“收到！下次干活时我就转告～”/“收到，我会转告的”
- 右键原有的“夸夸”菜单项并入“工作遥控 → 做得好”；原来的 `pending_praise` / `/praise/take` 已由反馈队列和 `/feedback/take` 取代（存档迁移见「持久化」）

**同意 / 否决的实现要点（v0.3 第二部分）**
- hook（PermissionRequest）：`AskUserQuestion` 不处理（那是提问不是授权）；`ExitPlanMode` 只向 `/event` 发 `{"type":"plan_ready"}`，不进入授权流程；其余工具先 `/permission/open`，再按 10 秒一段 `/permission/wait`。**只有响应是对象、`id` 对得上、`status` 恰好等于 `"allow"` 才输出 allow**；`"deny"` 输出 deny + 存档语言的理由（`ui.hook_deny`，默认“用户通过诗音否决了这个操作”）；其余一切（连不上、超时、`gone`、字段不对）都不输出任何决定。超时（存档 `remote.permission_timeout`，默认 120 秒）先撤回请求再退出。
- 显示的内容：Bash/PowerShell 显示命令（有描述则附 `# 描述`）；Edit/Write/NotebookEdit 显示文件完整路径；WebFetch 显示网址；WebSearch 显示搜索词；其他显示参数 JSON（不含已排除的 ExitPlanMode / AskUserQuestion）。最多 12000 字。**隐私模式不影响授权面板**（要决定就必须看到内容）。
- 面板（`panel.py:PermissionPanel`）：终端配色；内容区只读、约 6 行高，过长出现“展开/收起”；“还有 N 个”；“否决”“同意”两个大按钮。**不抢焦点、不响应键盘**（`WindowDoesNotAcceptFocus`，按钮子类忽略所有按键），按钮在每条请求出现后 0.6 秒内不可点。静音不影响面板，只影响那一句提示语。
- 排队：诗音每 100 毫秒从 hub 取最早的未决请求显示。用户在 CC 里自己答了以后**马上收起**：同一会话的 PostToolUse / PostToolUseFailure（同意后工具跑完，按工具名 + 参数配对）、Stop、UserPromptSubmit、Notification `idle_prompt`（否决后 CC 等输入）都会撤掉对应请求，面板收起或换下一条。兜底：hook 超过 25 秒没来轮询的请求视为已被 CC 取消。官方的 `PermissionDenied` 只在 auto 模式触发，手动否决授权框时不触发，所以不接。
- 服务端 `request_queue_size` 调到 64，并行子代理的 hook 同时连进来不会被重置。

**停下规则**（不弹面板）
- 工作遥控子菜单第一项“停下”。点了以后诗音说一次“好，马上停～”，切到挡手表情
- **下一个检查点**原地等待：调用工具之前（PreToolUse）或工具做完、开始写文字之前（PostToolUse），哪个先到算哪个。正在执行的命令不会被掐断；已经开始写的文字会写完（后面没有工具调用的长段文字拦不住，这是 hooks 机制的限制）。对所有会话生效（子代理的工具调用同样受影响）
- hook 第一次真的在检查点等着时，诗音说一次“已经停下啦～”（多个并行 hook、两段长轮询之间都不重复；不常驻）
- **暂停文字标签**：从 hook 第一次真的在检查点停住开始，诗音头顶右侧显示“暂停中 / Paused / 一時停止中”（`shion/badge.py`，独立小窗口，不会被台词盖掉；静音时也显示），直到点继续、在 CC 里说话、停满上限结束或立即中断解除停下。只是点了停下、还没到检查点时不显示。字体、背景、米白文字、橙色 1px 描边和圆角与气泡一致，按文字量宽，跟随窗口/宽画布/跳跃并夹进可用屏。悬停提示“点一下继续 / Click to continue / クリックして再開”。不抢键盘焦点，只响应左键；出现后 0.6 秒内按下无效，跨过时限再松开也不能误触；按住移出标签再松开无效。标签之外仍点穿（独立小窗口与圆角遮罩），点击复用菜单“继续”，放行所有等待检查点、收起标签并按原规则说“继续干活啦”。切换语言即时更新文字、提示和字体。
- 停下期间菜单里“停下”变成“继续”：点了就放行，无缝接着干，诗音说“继续干活啦”；还没到检查点就点 = 取消这次停下
- 其他出口：
  - 在 CC 里说话：任何一次 **UserPromptSubmit** 都解除等待
  - **30 分钟（`remote.pause_timeout`，可配置 60～1880 秒）没继续**：hook 返回 `continue: false`（PreToolUse 另带 deny）结束这一轮，其他并行等待的 hook 一起结束；诗音提醒一次“停太久了，这一轮先结束啦，在 CC 里说一声就能接着做”
  - 还没碰到检查点这一轮就自己结束了（Stop）：停下作废，不会挡住下一轮
  - 诗音没在运行、连不上服务器：hook 立刻放行，不会把 CC 卡住
- 实测（2.1.289）：`continue: false` 结束这一轮后 **不会再触发 Stop hook**，所以不会出现“做完啦”
- 静音只抑制气泡，停下照常生效

**立即中断**（工作遥控第二项，不切换窗口、不模拟键盘）
- 只对“工作中”的会话（见状态机 working）生效，没有工作中的会话时菜单项是灰的；对所有工作中的会话各做一次
- 校验 hook 报来的 CC 进程：还活着、名字和创建时间都对得上（防 PID 复用）。找不到时说“找不到正在工作的进程，先改成普通的停下啦”并退回普通“停下”
- 结束“在执行的工具开始之后才创建”的 CC 直接子进程及其子孙（先孙后子，核对创建时间）；排除 hook 进程（报来的 hook pid、可执行文件是项目 `.venv\Scripts\python.exe` 的直接子进程）。MCP 服务器等会话开始时就有的子进程不受影响。没有在执行的工具（正在写文字）时不结束任何进程
- 按会话中断时，如果选中的会话和**没选中、仍在工作的会话**报来同一个 CC 进程（pid + 创建时间相同），按进程结束会误杀另一个会话的工具：这个会话不结束进程，退回普通“停下”（只停它自己）；选中的会话之间共用进程不受影响（“全部”照常结束）。所有选中会话都因共用进程没法结束时说 `ui.interrupt_shared_process`（“这个会话和别的会话共用进程，先改成普通的停下啦”），而不是“找不到进程”；只有部分会话因此退回停下时照常说中断提示，不另外说话
- 同时给该会话设**一次性中断标记**：下一个检查点（PreToolUse / PostToolUse）返回 `continue: false`；被结束的工具触发的 PostToolUseFailure 不消耗标记，诗音也不说“出错了”。prompt / Stop 作废没用上的标记
- 点击后把会话标成空闲，下一次 prompt / PreToolUse 之前不会再发，并解除停下。即时提示分两种：确实结束了至少一个工具进程时说“命令停掉了，等它说完这句就停～”；没有结束进程（例如当时正在写文字）时说“等它说完这句就停～”。两种都用 stop 表情，中英日语义一致，不提前宣称这一轮已经中断
- 对应会话随后收到 `work_stopped` 时，说“已经中断啦，在 CC 里说一声就能继续”；若文字写完直接结束、只收到 `stop`（没有后续检查点），说“说完啦，这一轮停下了，在 CC 里说一声就能继续”（`interrupt_done_after_text`），不冒充实际中断。两种收尾都用 stop 表情、遵守当前静音，每个待确认的中断会话只提醒一次；静音时也清除待确认提示，不补播。普通停下/超时、其他会话及重复事件不触发收尾；新 prompt 作废待确认提示。沿用不计完成任务、不说完成台词及保留“继续”入口的规则
- 终端版和桌面端 Code 用同一种做法。**不用 Ctrl+C**：实测（2.1.289）用 `GenerateConsoleCtrlEvent` 向终端版 CC 的控制台发 Ctrl+C，CC 会在 1～4 秒内整个退出，而不是像按 Esc 那样只中断当前生成
- 限制：正在写、后面没有工具调用的文字拦不住（写完就是这一轮结束）

**按会话区分（2026-10-31，`feature/per-session-remote`）**
- 相关会话 = 此刻“工作中”“已停在检查点等待”或“待授权”的 Claude Code 会话（Claude 聊天、ChatGPT 不参与，仍只观察），按首次出现顺序。显示名 = 项目文件夹名；同一文件夹第 2、3 个会话加“ (2)”“ (3)”；隐私模式开启或拿不到文件夹名时用“会话 N / Session N / セッション N”（N 是在当前列表里的位置）。`shion/sessions.py`
- **没有活动中的 Claude Code 会话**：工作遥控整组置灰（包括“这一轮已结束”的继续），三语 tooltip 提示聊天不能从诗音暂停。工作中、检查点等待或待授权均算 CC 活动，只读聊天不算。
- **1 个相关会话**：工作遥控保留单会话结构（停下是 CC 全局暂停，反馈无归属）。
- **2 个及以上**：“停下 / 立即中断 / 做得好 / 有问题……”各自变成子菜单：各会话 + 分隔线 + “全部”；“有问题……”选完会话再弹原来的输入框。“继续”按同样规则：被停下的会话只有一个时直接一项，多个时子菜单。“继续（这一轮已结束）”只记最近一个会话，仍是直接一项。停下子菜单里已停下的会话置灰；立即中断子菜单里不在工作中的会话置灰；全局停下（选了“全部”）期间不显示“停下”
- “全部”：停下 = 全局停下（之后才开始工作的会话也停）并给此刻每个会话单独打上停下；立即中断 = 原行为；反馈 = 给点击那一刻的每个相关会话各放一份（好感度、表情、台词只算一次）
- 暂停（`RemoteHub`）：全局暂停 + 单个会话暂停 + 全局暂停中被单独放行的会话。会话 s 的检查点在 s 被单独停下、或全局停下且 s 没被放行时等待；**没有 session 的旧请求只看全局暂停**。放行某个会话时，若全局停下中已没有别的会话被单独停下、也没有别的 hook 在等，就整个解除全局暂停（只有一个会话时与原来完全一样）
- 结束这一轮：`end(session)` 只让此刻正在等的、属于这个会话的 hook 返回 stop（按会话的一次性代数），之后到达的不受影响；`end()` 仍是原来的全部结束。停满上限（`pause_timeout`）：全局停下中或旧 hook 没带会话时按原规则结束全部；只是这个会话被单独停下时只结束它
- 在 CC 里说话（`prompt`）只解除这个会话自己的暂停；`stop` 在这个会话没有 hook 在等时只作废它自己没用上的停下。不带 session 的旧事件仍解除全部
- 立即中断选了会话：只对这些会话找进程、结束工具、打中断标记、解除它们的暂停，别的会话的进程和停下不动；找不到进程时只把这些会话改成停下
- 反馈：队列项带可选 `session`（旧存档、0/1 个会话时点的 = 无归属）；每个归属各自最多 5 条。`/feedback/take` 带 session 取它自己的和无归属的，不带只取无归属的
- **检查点面板**：只有一个会话停在检查点时仍是原来的暂停标签，知道文件夹名且不在隐私模式时文字为“暂停中：{名称}”（否则仍是“暂停中”），点一下只放行这个会话（其他会话被单独停着时）或与原来一样放行全部。两个及以上会话同时停住时标签换成面板（`badge.CheckpointPanel`）：头顶右侧、底边落在标签中线向上展开、夹进可用屏；标题“暂停中”，每个停住的会话一行“名称（超过 24 字截断，全文在 tooltip）[继续] [结束这一轮]”，按开始停住的先后排。规则同授权面板：不抢焦点（`WindowDoesNotAcceptFocus`、`WA_ShowWithoutActivating`）、按钮只响应鼠标、出现或停住的会话变化后 0.6 秒内点击无效。“结束这一轮”之后照常走 `work_stopped`（不计完成任务、菜单可“继续”），诗音说“好，这一轮先结束啦，在 CC 里说一声就能接着做～”
- 临时关闭联动、静音、授权面板等逻辑不变；关闭联动时清掉全部（含按会话的）暂停

**这一轮结束后的继续**（实验见 `docs/experiments/send-continue.md`）
- 什么时候出现：诗音结束了某个会话的这一轮之后——立即中断后 hook 在检查点拿到 stop（`work_stopped`），或中断时正在写字、这一轮自己结束（该会话的 `stop`），或停满上限（`pause_timeout`）。只记**最近一个**会话。该会话再来 `prompt` / `working`（用户自己在 CC 里接着说了）就收起；其他会话的事件不影响
- 菜单：停下中仍是原来的“继续”（放行检查点），不变；没在停下时，在“停下”上面多一项：
  - **终端版**（hook 报的 `entry == "cli"` 且进程名 `claude.exe`）：“继续（发送“继续”） / Continue (send “Continue”) / 続ける（「続けて」を送信）”。点了在**单独的子进程**（`python -m shion.console_send`，QProcess，10 秒超时，同时只跑一个，发送中菜单项变灰）里做：只用 hook 报上来的 pid，先核对进程还在、名字是 claude.exe、创建时间一致 → `AttachConsole` → 读屏 → 逐字写 VK_PACKET + 回车 → `FreeConsole`。消息按存档语言：继续 / Continue / 続けて
  - **桌面端**（以及拿不准的情况，例如 hook 没报进程）：菜单项就叫“继续”，点了把“继续”（按语言）复制到剪贴板，诗音说“已经复制好啦，去 CC 里粘贴发送就行～”。不注入任何东西
- 读屏规则（`console_send.check_screen`，宁可不发）：
  - 最下面 25 行出现确认字样（Do you want / Yes / No, / Allow / allow / trust / 允许 / 信任 / Enter to confirm / Esc to cancel / Enter to select / proceed?）或带选中标记的编号选项（`❯ 1.` / `> 1.`）→ 不发（`dialog`）。回复里碰巧有这些字也不发；回复里不带标记的普通编号列表不算
  - 找不到“上下两条 `─` 横线夹住、以 `>` / `❯` 开头”的输入行 → 不发（`no_input`）
  - 输入行去掉提示符后必须是空的；唯一例外是 CC 的灰色占位提示 `Try "…"`，且控制台光标正好停在提示符后面（读屏分不出颜色，光标位置能区分：用户打过字，光标会跟在字后面）。否则 → 不发（`draft`）；输入不止一行也算 `draft`
- 结果台词：发出 → “发过去啦，接着干～”并收起这一项；`draft` → “输入框里还有没发出去的字，我就不动啦”；`dialog` → “屏幕上像是有确认框，我不替你按回车哦”；进程没了 / 找不到输入框 / 出错 → “没找到那个终端，去 CC 里说一声吧”。没发出去时这一项保留，可以再试（进程已经没了的除外）
- 实测（2.1.289，conhost 和 Windows Terminal）：空输入框能送达且前台窗口不变；有草稿、信任文件夹对话框、权限确认框都不发，草稿原样保留。限制：依赖 CC 现在的界面文字和输入方式，改版后要重新调整；读屏和写入之间用户恰好在打字，仍可能拼在一起

**hooks 配置**
- PermissionRequest、PreToolUse、PostToolUse 的 hook 超时要设得比上面的等待时间长（例如 PermissionRequest 180 秒、PreToolUse / PostToolUse 1900 秒），由 hook 脚本自己控制提前返回
- 实现后要在 CC 终端版和桌面端 Code 标签页里实测：授权请求能否被诗音接管、暂停时 CC 界面显示什么。结果记录到 progress.md

```json
    "id": "headpat",
    "name": {"zh": "摸摸头", "en": "Headpat", "ja": "なでなで"},
    "responses": [{
      "text": {"zh": "只准摸一会儿哦……", "en": "Just for a moment, okay…", "ja": "少しだけだよ……"},
      "expression": "happy"
    }]
  }]
}
```

- 零食文件还含三语 `full_response`；晚安条目含 `"action": "sleep"`。缺少某语言时回退中文，名称和回应必须有中文；同类同选项同语言不连续重复回应。
- 只接受 `schema_version: 1`（整数），`id` 唯一、回应非空；表情限 happy/proud/stop/dizzy/idle/neglect2，动作只支持 sleep（零食不能附带动作）。坏文件或不支持的版本禁用相应列表，坏条目/重复 id 跳过并记录日志，窗口显示内容不可用提示。仅解析数据，不执行 JSON 中的代码。
- 界面通用文字仍在 `assets/lines/{zh,en,ja}.json`。v0.4 只加载内置内容；导入、安装、管理在 v0.5 实现。

## 好感度系统（v0.4.1）

让好感度真正有作用：越相处越亲近。**不做好感下降**（几天不开电脑回来掉好感会让人有负罪感；冷落情绪交给已有的 neglect 临时状态表现）。

**数据驱动**：等级、阈值、名称、解锁内容写在 `assets/affection.json`（带 `schema_version`），代码里不写死，方便以后调平衡（内容包不能修改等级和阈值，只能让新内容带 `min_level`）。

**每日获取上限**（防止狂摸刷满；数值写进 json，以下为初始值）
- 摸头：每次 +1，每天最多 +20
- 喂零食：每次 +2，每天前 5 次有效（已实现，迁移到统一的每日上限逻辑）
- 预设对话：每个选项每天第一次 +1
- 首次启动问候、每天第一次打开：+2
- 每日计数按本地日期跨天清零；双击状态里可看“今天还能获得 X”
- 新系统启用后，“做得好”只加入工作反馈队列，不再额外加好感；配置失效时保留原先 +3 的行为。摸头达到好感上限仍可交互、统计次数；未吃完的零食不消耗次数。跨午夜喂食计入完成当天。
- 存档 v5 保存 `affection_level` 和 `affection_daily`（日期、摸头/零食/打开次数、当天已奖励的对话 id），保留旧 `snacks` 记录兼容已有存档；迁移时当天已有摸头和喂食计入额度。重启不重置额度，跨天不自动发打开奖励，需当天真的打开。

**等级**（初始阈值，用了几天后再调）

| 等级 | 累计好感 | 中 / 英 / 日 |
|---|---|---|
| 1 | 0 | 初识 / Acquainted / 初対面 |
| 2 | 50 | 熟悉 / Familiar / 顔なじみ |
| 3 | 200 | 亲近 / Close / 仲良し |
| 4 | 500 | 信赖 / Trusted / 信頼 |
| 5 | 1000 | 知音 / Kindred spirit / 知音 |

- 升级时：高优先级气泡说一句该等级专属的升级台词 + 一圈爱心（一次性，不受爱心限流）。当前等级写进存档，旧存档按已有好感直接算出等级，**不补播**升级台词
- 双击状态显示等级名和到下一级的进度
- 进度是“本级已获得 / 本级升至下一级所需”；满级显示“已满级”且仍可累计好感。“今天还能获得”只计当前已解锁的预设对话，解锁后立即更新。
- 迁移、重启或修复配置仅重新建立等级基线，不补播；一次奖励跨多级时仅播最终等级一次。升级气泡遵守静音，一圈 12 颗爱心独立于普通摸头粒子的间隔和总数限制。

**解锁**
- 对话选项、零食、自言自语台词都可以带 `min_level` 字段；未达到等级的不显示（不显示“未解锁”占位，保持惊喜感）
- 初始内容分配建议：“陪我一下”需要 2 级；新增 1～2 个高等级专属对话和零食；每个等级各有几句专属的自言自语，等级越高越亲近
- 5 级“知音”时，偶尔（低频）主动说“谢谢你一直陪着诗音”之类的话
- 本版内容：2 级“陪我一下”、3 级“听我说说”、4 级“分享巧克力”、5 级“以后也陪着我”；每级 3 句自言自语、各 2 句摸头和冷落回归台词，均有中英日原文。台词兼容旧字符串和 `{ "text": "…", "min_level": 3 }` 对象；菜单不显示锁定占位，选择入口也检查等级。
- 感谢台词只在原来的自言自语机会中抽取：初始概率 5%，两次至少间隔 1800 秒；这两个值写入 `affection.json`，不提高整体自言自语频率。

**反应随等级变化**（在现有概率基础上乘系数，系数写进 json）
- 戳她：等级越高，挡手、晕的概率越低，普通开心反应越多（例如 1 级 ×1.2，5 级 ×0.6，并保证概率总和合法）
- 五级系数初值为 1.2 / 1.0 / 0.85 / 0.7 / 0.6；同时乘挡手和晕概率，若总和超过 1 则按比例归一，余量为普通反应。
- 摸头台词：按等级选不同的台词池（低等级更别扭，高等级更撒娇）
- 被冷落回来时的台词也按等级区分

**测试要点**：跨天清零、各上限边界、等级计算与迁移、升级只触发一次、`min_level` 过滤、概率系数后的边界、json 缺失或损坏时回退到“只有计数、不分等级”的旧行为

**配置回退**：只在正式启动时加载配置；缺失、坏 JSON、不支持的版本或关键字段不合法则禁用等级与新每日奖励逻辑，使用旧摸头/零食/反馈计数、原始概率、通用台词和无等级过滤的菜单。保留已有等级/每日存档字段；修复配置并重启后按累计好感重新计算等级，不补播升级，并用当天交互统计补齐回退期间的摸头、喂食额度。

## 内容包（v0.5）

类似创意工坊：别人为**诗音**做好新内容发到 GitHub，其他人下载就能用。**角色永远只有诗音**：内容包只能给诗音增加说的话、零食和对话，不能替换角色、不能替换精灵图。

- **只允许数据，不允许代码**：内容包里只能有 json（以及零食图标这类小 PNG，见下）。加载时只解析允许的文件，忽略其他一切；解压时防止路径穿越（`../`）和超大文件（单个文件、总大小都设上限）
- **类型**（一个包可以包含多种）：
  - 台词包：给诗音新增台词，或新增一种语言的翻译（例如韩语）；可以给已有台词分类追加句子，**不能删除或覆盖**内置台词
  - 零食包：给“喂零食”菜单新增零食（可带 `min_level`、可选一张 ≤128×128 的小图标）
  - 对话包：给“对话”菜单新增预设选项和回应（可带 `min_level`、表情、动作，表情和动作只认现有白名单）
- **不支持**：替换或新增精灵图、修改好感等级和阈值、修改 hooks/遥控相关的任何行为
- **格式**：`manifest.json`（`id`、`name`、`version`、`author`、`license`、`types`、`min_shion_version`、各语言的名字和简介）+ 按类型分的子目录。诗音自带的台词、零食、对话也整理成同样的格式（内置、不能删除）
- **安装**：把 `.zip` 拖到诗音身上，或右键“导入内容包”；安装前显示名称、作者、许可证让用户确认。安装到 `%APPDATA%\Shion\packs\`
- **管理**：右键“内容包”：勾选启用/停用、查看详情、删除
- **给制作者**：模板仓库（带说明的空白包）；`tools/validate_pack.py` 检查 json 格式、字段、语言、白名单、图标尺寸并给出具体报错；README 里写“诗音的人设说明”（性格、口癖、称呼方式、不会说的话），帮助大家写出像她的台词
- 社区索引（`shion-packs` 仓库 + 应用内浏览）暂不做，等有人做了内容包再说

## 可测试性要求（重要）

CC 看不到屏幕，所以设计上必须让大部分东西能**不靠人眼**验证：

- **状态机是纯 Python**：`state.py` 不能 import Qt。时间通过参数传入（例如 `now: datetime`），不能在内部直接调用 `datetime.now()`，这样“2 小时后进入冷落”可以在测试里瞬间模拟。
- 测试用 `pytest`，放在 `tests/` 下。运行方式：`.venv\Scripts\python -m pytest -q`，只看失败的输出。
- **调试截图模式**：`python -m shion --snapshot out.png [--state happy] [--bubble "文字"]`，离屏渲染一帧存成 PNG 后退出。`--from-state idle --state happy --at 0.06` 可检查淡化中间帧；不传 `--from-state` 时直接显示目标状态。CC 需要检查画面时，生成截图再打开看，**只看截图，不要打开 assets 里的原始素材**。
- 截图动作参数互斥：`--jump`（原地小跳，`--at 0～0.5`）、`--nod`、`--gesture pinch|pat|knock|tickle|lift`（让 V3 动画器按确定性输入走到手势的第 `--at` 秒，输入来自 `v3proto` 的 `*_scenario`）；`--side left|right` 指定鼓脸颊的一侧且不自动换边。可组合状态、三语气泡。已移除 `--mirror` / `--walk` / `--face`，以及 v3.0.0 起的 `--cheek` / `--tickle` / `--drag` / `--weight-shift` / `--desk-blink` / `--renderer`（传了会被 argparse 拒绝）。截图不创建 FPS 窗口，也不计实际绘制次数。
- `--from-state idle --state happy --at 0.1` 检查表情交叉淡化的中间帧（V3 在 0 秒仍是旧表情的脸）；可配合 `--activity quiet` 隔离待机摇摆。
- `--height 160|200|260|320` 和 `--activity quiet|normal|lively` 检查四档大小/活跃度。常规 `--at 1.125/3.375` 检查慢摇摆两端，`--state neglect1 --at 1.5` 检查呼吸峰值，`--state working --at 2` 检查工作呼吸。
- 睡眠截图自动合成 Z：`--state sleep|bed --at 0/.9/1.8/2.2` 检查单枚/多枚、漂移与淡出，截图重建历史发射时刻但正式运行不补发。`--state working --nod --at 0/.2/.4` 检查点头，`--state neglect2 --at .875/2.625` 检查慢摇两端；`--nod` 与其他截图动作参数互斥。
- 截图 `--panel permission|input [--panel-text 内容] [--panel-more N] [--panel-expand] [--lang ja]` 只画遥控面板。
- 截图 `--panel dialogue|snacks|eating [--lang zh|en|ja]` 检查对话首页、零食页或 happy 与碎屑效果；只查看此入口生成的截图，不打开精灵原图。
- **README 媒体**：`.venv\Scripts\python tools\make_media.py` 在 `docs/images/` 生成 4 秒、20 fps、480×360 的 `hero.gif`，以及统一 720×420 的 `pat.png`（爱心）、`desk.png`、`permission.zh/en/ja.png`（带诗音，命令 `npm test`）、`sleep-bed.png`（Z）。其余场景无台词气泡。全部用不透明浅色圆角卡片，以 2 倍像素渲染再 Lanczos 缩小；文档引用使用相对路径。
- 媒体与旧截图共用 `SnapshotScene` / `render_snapshot` / `render_snapshot_panel`，同一进程连续推进假时钟、复用宠物窗口；旧 `--snapshot` 参数、输出及真实屏幕定位不变。媒体单独固定种子 42、时钟起点 100.0、DPI、区域设置、字体与虚拟布局，使用 Windows Qt 原生字体但不显示窗口；不读取用户存档、连接配置或桌面，不启动逐帧子进程。缺少固定字体时明确失败，不静默替换。
- 媒体在相同 Windows、字体文件、Python/Qt/Pillow 版本下要求逐字节一致；跨系统或字体/依赖版本不保证一致。无编码时间或机器信息；GIF 共用全局调色板、无抖动、无限循环且解码首尾一致。GIF ≤2,000,000 字节、单 PNG ≤300,000 字节、目录总量（含已有其他文件）≤5,000,000 字节，超限退出失败。先在临时目录生成并校验，成功后只替换上述七个文件，保留其他文件。`--output-dir` 可指定重跑校验目录。
- **调试模式**：设置环境变量 `SHION_DEBUG=1` 时，冷落、睡眠的阈值缩短为秒级，并在控制台输出状态变化日志；诗音旁显示 FPS，每 0.5 秒按实际经过时间统计桌宠 paintEvent 次数。计数器独立刷新、透明点穿、不抢焦点，跟随移动与大小变化且限制在屏幕内，随桌宠隐藏/关闭。普通模式不创建该窗口。它表示 Qt 绘制频率，不代表显示器呈现频率；定时器、render_frame 和计数器自身绘制不计入。保留静止画面的重绘优化，静止时 FPS 较低是正常现象。
- 程序日志写进 `%APPDATA%\Shion\shion.log`，不要大量打印到终端。

## Codex 不自动拉起诗音（2026-10-31 决定）

- **决定**：Codex 观察端（`shion/codex_mcp.py`，入口 `Shion.exe --codex-observer`）只做事件转发、2 秒心跳和租约，**不拉起诗音**。`668962c` 加入的“收到 SessionStart 且命名管道不存在时拉起”已删除（`autolaunch()`、`codex_link_enabled()`、`_AUTOLAUNCH` 及 `dispatch()` 中的调用，连同 `launcher.AutoLaunch` 及其冷却逻辑）；`git diff d907e33 -- shion/codex_mcp.py` 为空。Codex 用户改为在右键菜单 → 设置中开启“开机自启”，三语 README 的常见问题里已写明。
- **原因（诊断结论）**：Codex 把 MCP 观察端放进设置了 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 且不允许脱离（breakaway）的 Job Object。观察端拉起的诗音即使带 `CREATE_BREAKAWAY_FROM_JOB` 也留在这个 Job 里，Codex 退出或关闭 MCP 子进程时，Job 关闭，诗音被一起结束，所以这条路径做不到“拉起后独立存活”。Claude 的 hook 子进程不在这样的 Job 里，行为不受影响。

## V2.1 诗音周报与体力（2026-11-03：第 2 步开发预览，待验收）

只做 Claude Code，不做 Codex/ChatGPT。目标是给诗音一个值得晒、值得宣传的功能。用户 2026-11-02 已同意：为统计 token 改动下方隐私规则；周报带 API 价格估算。

### 隐私规则（本版改动）

- hook 仍**不打开** `transcript_path`，`Stop` 规则不变。token 统计由**诗音主程序**在后台线程只读扫描 CC 本地对话记录。
- 扫描只取 `type == "assistant"` 且带 `message.usage` 的行中的：`timestamp`、`message.id`、`requestId`、`message.model`，以及 usage 的 `input_tokens`、`output_tokens`、`cache_creation_input_tokens`、`cache_read_input_tokens`，以及 `usage.cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens`。最晚活动与夜猫子只使用 user / assistant 对话记录的 `timestamp`（不读取内容）。**绝不读取、保存、记录或显示**对话内容、`cwd`、文件路径和项目目录名；日志中只写计数。
- 落盘只含按本地日期/模型/档位的数字聚合，以及增量扫描状态：文件偏移与哈希去重索引。最近 8 天的去重索引只含消息键的 sha256、聚合桶定位、上次 token 数与数值时间戳，用于跨重启的重复排除和流式差额修正，不保存明文 message.id / requestId。缓存里的文件以路径 sha256 前 16 位作为键，不存明文路径；只存偏移、文件标识/大小/修改时间和边界摘要等重扫校验信息。
- 设置菜单新增“统计用量”开关，默认开启。关闭后不扫描，周报里隐藏 token 和价格两行，七天柱图改为任务计数。隐私模式不影响用量统计，因为它们只是数字。

### 数据源 A：token 用量（`shion/usage.py`）

- 目录：设置了 `CLAUDE_CONFIG_DIR` 时用 `<它>/projects`，否则用 `%USERPROFILE%\.claude\projects`，递归读取其中的 `*.jsonl`。目录不存在就视为没有数据，不报错。
- 逐行流式读取：先用 `'"timestamp"' in line` 预筛，再只保留白名单元数据；user / assistant 的 timestamp 用于活动统计，仅 assistant 且有 usage 的记录进入 token 聚合。坏行跳过并计数，单行超过 1 MB 也跳过。
- **去重**：同一条回复会被写入多次，按 `(message.id, requestId)` 去重，两者都缺失的行不计入。增量扫描的去重集合只保留最近 8 天的键。
- 文件被截断或替换（大小小于已记偏移）时，从头重读该文件。去重集合保证不会重复计数。
- 时间戳按本机时区换算成本地日期，日界是 00:00。`usage.json`（位于 `%APPDATA%\Shion`）只保留最近 8 周的每日聚合：`{date: {model: {tier: {in, out, cw5, cw1, cr}}}}`（聚合键为日期、模型、单消息档位）。cache write 按 5 分钟 / 1 小时分别累计，缺少细分时全部按 5 分钟；总 token 只算一遍 cache write。写入方式与存档相同：先写临时文件，再原子替换。
- 触发时机：启动后 10 秒、每次 `Stop` 事件后（30 秒防抖）、打开周报时。扫描在后台线程进行，不阻塞 GUI 和 hook 响应。
- “总 token”是 input + output + cache write（cw5 + cw1）+ cache read，“输出 token”只算 `output_tokens`。每条有效消息先按 input + cache write + cache read 选价格档位，再聚合；价格不落盘，渲染时按当前单价计算，改价格无需重扫。
- 去重的流式更新采用时间戳较新的有效 usage，并用差额修正聚合；去重键持久化为 sha256。增量文件校验边界摘要，截断/替换或晚到旧记录时从源重建，避免超过 8 天的重复键再次累加。未完成的末尾行不前移偏移。
- 最晚活动与夜猫子从对话记录 timestamp 转为本地时间，按 05:00 划分活动日，只保存每日最晚分钟数；不从诗音运行时间推断。

### 数据源 B：终端额度（statusLine）

- 第 0 步已确认：桌面版 Code 标签页不运行 statusLine；终端版运行，`rate_limits` 在首条回复后出现。此数据源只用于终端四档体力及可获取的额度数字。
- CC 把 statusLine 的 JSON 通过 stdin 传给 statusLine 命令。Pro/Max 订阅从会话的第一条回复之后开始带 `rate_limits.five_hour` / `rate_limits.seven_day`，各含 `used_percentage`（0～100，可能超过 100）和 `resets_at`（Unix 秒）。每个窗口都可能单独缺失，API 账号则完全没有。
- 新增入口 `Shion.exe --statusline`（源码运行时为 `hooks/shion_statusline.py`，只用标准库）。它读完 stdin，只取上述 4 个数加上 `session_id`，带令牌 POST 到 `/usage/limits`，超时 0.3 秒；失败时静默。其他字段一律不转发。
- **与用户已有的 statusLine 串联**：连接时如果 `settings.json` 里已有第三方的 `statusLine`，把它的原值原样保存到诗音的安装记录中。之后运行时用同一份 stdin 调用原命令（超时 1 秒），把它的 stdout 原样输出。没有原命令时什么都不输出。断开时按字节恢复原值。保留原 statusLine 的 padding 等布局选项。Windows 与 CC 一样优先 Git Bash（支持 CLAUDE_CODE_GIT_BASH_PATH），没有时使用 PowerShell；路径使用正斜线并按对应 shell 引用，不通过 cmd 改变原命令语义。官方依据：[statusLine Windows 配置](https://code.claude.com/docs/en/statusline#windows-configuration)。
- 安装记录位于目标配置旁的 `settings.json.shion-statusline.json`，保存原 JSON 值的原始字符/转义/内部空白和当前接管值；不存在原字段与原值为 null 分开处理。记录与配置一起走备份/原子替换事务，失败时只回滚仍等于本次写入内容的文件。断开清空活动记录。接管项或记录缺失、损坏、被外部改变时，**连接**拒绝覆盖；配置其他字段的正常修改保留。准备前及每次替换前核对读取时的文件字节，并检查全部事务依赖，冲突即停止。
- **断开的宽松路径（V2.1.0 审查修复）**：接管项或记录被改过时，断开仍要照常移除诗音的 hooks，不能因为 statusLine 而卡住。statusLine 仍是诗音自己的命令（命令里有 `--record` 和本连接的记录路径，并且有 `--statusline` 或 `shion_statusline.py`；别人带 `--statusline` 的命令不算）时，记录里有可解析的原值就恢复原值，否则删掉这个键；statusLine 已经是别的命令时原样保留，并提示「statusLine 已被改动过，诗音没有动它」。记录文件损坏时改名成备份保留，不删除。
- 断开时只有 statusLine 的值按字节恢复，settings.json 的其他部分会按 2 空格缩进重新排版（键和值不变，同 2.0）。
- **执行原命令的安全约束**：查找 shell 时不搜索当前目录（Windows 上 `shutil.which` 会先查 cwd，项目里放一个 `bash.exe` 就会被执行），只看 `PATH` 中的绝对路径目录；`CLAUDE_CODE_GIT_BASH_PATH` 必须是存在的绝对路径；PowerShell 固定用 `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`。原命令放进一个 Windows Job Object，超时时整个进程树一起结束；按时完成时不结束它留下的后台进程。输出超过 64 KB 视为失败。
- **输出缓存**：`%APPDATA%\Shion\statusline-last-<项目目录 SHA-256 前 16 位>.bin`（项目目录取 stdin 的 `workspace.project_dir`，没有就用 `cwd`），各项目只回放自己的上一行，文件名里不出现路径。原子写失败时删除临时文件；安装记录已不在时不写。断开时删除全部 `statusline-last*.bin` / `*.tmp`。
- 写入、断开和备份全部走 `tools/hooks_config.py` 现有的事务、备份和并发检测逻辑，“已连接”的判定加上 statusLine 这一项。修改 spec「一键连接」中“statusLine 保留”那条规则时要同步更新：诗音只接管自己写入的那一项，并负责恢复原值。
- 数据超过 `resets_at` 后视为过期，过期或从未收到时显示为“未知”。

### 体力（终端四档、桌面两档）

**终端：statusLine 四档，只用 five_hour。**

| 已用 | 状态 | 表现 |
| --- | --- | --- |
| < 50% | 精神 | 正常 |
| 50～80% | 打哈欠 | 待机表情用 `yawn`（替换原 blink 替代图） |
| 80～95% | 趴下 | 待机改为 `slump` |
| ≥ 95% | 倒地 | 待机改为 `collapse`，台词“今天……撑不住了……” |

- 终端首次收到有效窗口时精神档也有一句台词（不跳跃）；进入每一档时说一次三语台词，同一个 5 小时窗口内每档最多一次。下一次窗口刷新（`used_percentage` 回落到 50 以下，或越过 `resets_at`）后播放“满血复活”：跳一下并说一句台词。
- v5 存档可选字段 `stamina_announced` 只保存窗口重置时间与已播档位枚举（含一次复活标志），不含会话标识、百分比或内容；最多 128 个窗口。重启后继续去重，过期记录不再参与判定。缺失或非法字段忽略，不升 schema。
- 多会话在内存中分别保存两个窗口和 hook 信号；展示各窗口仍有效观测值的最大值，任一未知客户端的有效倒地信号都使待机倒地，必须对应会话的复活信号才解除。收到 statusLine 的同一会话走终端路径，其 hook 不再另设两档倒地锁；不能根据项目名、进程、消息或时间猜客户端。单个缺失/过期窗口不使用另一个窗口代替，不因字段缺失播报复活。只记录本次实际收到且未过期的 seven_day 到收到日，不能把其他会话的旧值再记到今天。临时关闭 Claude 联动会清空内存额度/体力，关闭期间不接收。
- **桌面：hook 两档，正常 / 倒地。** 按数据源 C 的两个信号切换；倒地使用 `collapse` 图和同一台词，复活时跳一下并说一句台词。只在状态变化时播报，不因重复事件重播；没有信号时正常待机，不猜额度。四档体力仅终端可用。
- **铁律**：体力只改变待机外观。授权面板、检查点面板、暂停/继续/中断、拖动、固定表情、喂零食都优先于体力状态。倒地时来了授权请求，必须照常弹出、照常可点，面板打开期间诗音临时站起来。
- 体力播报和复活跳跃也等待空闲及现有气泡结束；有授权、输入、周报、连接引导或检查点面板时延后，只保留当前仍适用的一条，不补播已过时的档位。
- **不按 token 推算额度**：额度里各模型的权重和上限没有公开，普通聊天的用量在本地看不到，用 token 推算出的百分比会误导。体力和额度数字只来自 statusLine 的 `rate_limits` 和 hook 信号；周报的 token 统计只用于展示，不换算成额度。
- 终端额度未知时隐藏四档体力，不猜测，也不显示错误状态；桌面仍按有效 hook 信号显示两档。双击状态气泡只在有有效数字时增加“5 小时额度 42% · 7 天额度 73%”一行，未知时不显示，不能从桌面两档信号生成额度数字。5 小时额度只用内存中未过期的数值，不做 token 推算。7 天额度用**最后已知值**：v5 存档可选字段 `seven_day_last = {value, resets_at, at}`（不含会话标识）在每次收到未过期的 seven_day 时更新，数值或重置时间变化、或距上次写盘满 10 分钟才写盘；未过 `resets_at` 时显示，收到超过 5 分钟就附上时间，如“7 天额度 73%（3 小时前）”（分钟 / 小时 / 超过 48 小时按天）；过期、缺失或非法时隐藏。临时关闭联动期间整行不显示，但不删除最后已知值。

### API 价格估算

- `assets/pricing.json`：按明确模型版本匹配（仅允许日期 / latest 后缀，不用 claude-opus-4 这类宽前缀；未知版本一律未计价），填写每百万 token 的 input / output / cache write 5m / cache write 1h / cache read 美元单价。支持可选档位阈值，按每条消息的 input + cache write + cache read 判断（超过阈值才进高档），不按一日/一周的聚合总量判断。仅采用官方定价页的数字，写明 `as_of` 与来源；提交前先给用户核对价格表。只改单价无需重扫，修改分档阈值则需重建聚合。

## V2.2 Claude 桌面版聊天联动（v2.2.0 发布）

目标：在 Claude 桌面版普通聊天里让 Claude 做耗时任务（如做 PPT）时，诗音也能显示“在干活”并在完成时提醒。Claude 的聊天和 Claude Code 共用额度，聊天本身也会干活，这是诗音区别于只看编程工具的卖点。

**外部信号探测结论（2026-11-04，`tools/probe_chat.py`，报告 `build/probe-chat-report.md`）**：UI Automation（Chromium 默认不暴露网页区无障碍树，读不到“停止”按钮）、Shell Hook 任务栏闪烁、窗口标题、`%APPDATA%\Claude\logs` 均无可靠的开始/结束信号。强制开启无障碍（启动参数或系统屏幕阅读器标志）会改用户配置、拖慢长对话，并让完整对话进入无障碍树，**不采用**。Windows 通知（桌面版“回复完成”开关已开）的长任务重测结果见 progress；若可靠，可作为“完成”信号的补充，但不作为主路径。

**采用方案：诗音提供本地 MCP 服务，由 Claude 主动通知**
- 新入口 `Shion.exe --chat-mcp`（stdio，只用标准库，不加载 Qt），复用 `codex_mcp.py` 的协议骨架和令牌通道。只提供三个工具：
  - `shion_working(task)`：开始一个需要用工具或预计超过 30 秒的任务前调用；`task` 为几个字的任务名（清理控制字符，最长 20 字），隐私模式下不显示
  - `shion_done()`：上述任务完成时调用
  - `shion_need_input()`：需要用户回来确认或回答时调用
- 工具说明与 MCP instructions 逐字沿用步骤 0 探针。连接后由用户复制一句个人偏好，中文沿用实测原句，英日采用同义译文，均只提 working/done。need_input 单独显式验收。英日自然调用各一长一短，留到步骤 2 真机验收。
- initialize 回复后通知上线，stdio 关闭时通知下线。诗音内按 MCP 进程实例区分连接；工具通知最多等待 0.4 秒，通道失败即放弃并正常回复，无重试或探针日志。
- 诗音侧显示为独立的“Claude 聊天”来源：只观察和提醒，不提供授权/暂停/中断控制；不读取、不接收对话内容。
- 工作遥控只作用于 Claude Code：没有工作中、检查点等待或待授权的 CC 会话时整组置灰，三语 tooltip 提示“Claude 聊天无法从诗音暂停，请在 Claude 里点停止”。执行暂停时再次检查活动会话，旧菜单也不能留下无对象的暂停标记；没有 CC 活动的遗留暂停在同步时解除，但要等距最近一次 CC 活动超过 30 分钟（`STALE_PAUSE_GRACE`，与工具最长保持时间一致；从未见过 CC 活动则立即解除）：CC 长时间思考可以几分钟没有 hook 事件，而“工作中”5 分钟就过期，不能因此悄悄解除用户的暂停（v2.2.0 发布前审查修复）。旧 hook 无会话标识时仍按实际工作/等待状态判断。
- 聊天与 CC 同时工作时，只暂停 CC；聊天来源继续保持工作状态，本体仍显示工作中。暂停请求和到达检查点的气泡三语说明“只暂停 Claude Code，Claude 聊天仍在继续”；检查点标签/面板在聊天工作中时明确标注 Claude Code。聊天 need_input 不生成授权请求，CC 的真实授权面板仍独立有效。
- 兜底：`shion_working` 之后 15 分钟未收到 `shion_done`，自动回到空闲（不播放“做完了”）；同一时间只跟踪一个聊天任务，新的 `shion_working` 覆盖旧的。
- 限制：只支持 Claude 桌面版（网页版、手机 App 连不到本机）；由 Claude 主动调用，可能偶尔漏调。README 三语写明。

  - B. 生成 Desktop Extension 安装包（`.mcpb`，`server.type = binary`），用户双击安装；需确认能否指向已安装的 `Shion.exe`，或须在包内附带独立的小程序

### 独立被捏反应（2026-11-07）

- 取代“抓取时保持当前表情”的用户交互。几何层仍固定眼嘴位置；独立 reaction 层覆盖五官，不改变 Settings.expression。有效按下抓取原表情，一整轮固定皮肤/脸颊材质/头发边界，表情变化只替换五官。
- 默认顺序：0–0.2 秒 surprised，身体以胯缩约 1.5%、头随脖子、脚不移动；之后 dizzy 眼嘴，不含星星，双臂绕各自肩轴镜像摆动 4 Hz/约 ±3°；持续 >2 秒或向外拉伸超过上限 70% 后锁定 teary，手臂 6 Hz/约 ±4.5°。普通越阈值先完成惊讶，升级后当次抓取不降级。
- 松手提前终止抓取阶段，显示 angry（鼓嘴）；手臂用连续弹簧停止，头随脸颊回弹绕脖子轻晃、约 ±1.2° 内。脸颊实际停稳后保持 1.5 秒，再用 0.35 秒 smoothstep 淡回最初原表情；不采用固定时间截断物理回弹。回弹仍默认 3 Hz、ζ≈0.3。
- 彩蛋用真实单调时钟的滚动 10 秒窗口，每次有效左脸颊按下计数，包括回弹/保持/淡回中重抓。第 3 次及以后直接 teary，跳过惊讶/晕乎，松手仍 teary；彩蛋标志锁定到该次反应结束。重抓接续当前几何位移，始终恢复整轮最初原表情。
- 参数由不可变 ReactionParameters 在每次有效按下时快照；面板可调惊讶时长、委屈等待、拉伸比例、回弹时间倍率、回弹后保持、淡回、彩蛋窗口及两档摆臂速度/幅度。阶段时钟与有界物理步长分离。阶段切换重排眨眼，不禁用长期按住时的正常眨眼。
- 原表情选择在反应期间锁定，面板显示阶段及本次窗口内计数。失焦松手；关闭捏脸/恢复默认取消反应、恢复原表情并清空计数。鼠标按下与拖动使用同一头部逆映射，包含回弹轻晃。与后文敲摸共用反应覆盖和原表情恢复机制，无台词或 shion 接入。
- 普通动画共用完整头部合成/位移网格；普通动画全关时使用精确静止合成，加同一局部脸颊与五官覆盖及连续二级运动，保证淡回末帧无全画面跳变。源图、切片、参考资源与依赖不变，rig 保持 v2。用户验收动态手感，离屏截图与自动测试不能替代；持续被捏稳定 60 FPS 目标仍未完成。

- 2026-11-08 返修约束：先清除最初表情的完整眼线/眼影，再形变脸颊，最后叠加当前反应五官；得意原眼线不得按共用眨眼发梢遮罩保留。眉毛跨刘海时不按眼睛裁切。脸底软边以预乘透明度叠加到现有画面，不能将不透明头发替换为半透明像素。脸颊移除遮罩须覆盖全部持有原描线的头部层（含刘海、鬓发），避免向内回弹时出现原位置旧轮廓；零位移及淡回结束保持原基线。

### 独立敲头、摸头与随机金星（2026-11-08 阶段成果）

- 产品实现仅在 `v3proto/`，沿用 rig v2、当前八款表情、完整头部网格、五官清除及覆盖、肩/胯/脖子转轴与弹簧。不导入旧版交互，不接入 `shion/`，不读取个人配置；无好感奖励、台词或工作联动，不改原图、切片和垫底，不加依赖。
- 头顶、刘海、呆毛的实际可见区域支持敲摸，使用当前网格逆映射及 alpha 命中；左侧鼓脸颊优先捏脸，其余头发保留拨动。单次头顶按住始终在 6 个 Qt 逻辑像素容差内，松手算敲头；双击按两次处理。水平拖动达到 12 个逻辑像素进入摸头，不受显示缩放/DPR 改变阈值；超过点击容差后松手不补敲，仅按住或竖向移动不触发摸头。
- 每次敲头立即 `teary`，整头（五官、头发、饰物）一起下沉约 28 原图像素并回弹，身体和脚保持原位。默认位移时间线 0.28 秒，保持委屈 0.9 秒，随后 0.35 秒淡回最初原表情。相邻敲击间隔 ≤1.5 秒，第 3 下将保持延长为 2 秒；延长期间继续敲会刷新保持时间，连敲与捏脸计数独立。
- 下沉阶段后，金星从实际点击的画布世界坐标向上/向外蹦出，不跟随头部回弹漂移。每次随机 6–10 颗，展开半径 36–44 原图像素（略小于手掌），随机初速度、方向、旋转及寿命；重力为 900 原图像素/秒²，约 1 秒内下落、缩小并淡出。金星由 QPainter 五角星、暖金渐变及轻柔光绘制，无新增图片资产。随机参数只在点击时生成，绘制采样不改变轨迹；实际预览使用独立随机流，快照按 `--seed` 复现，不扰动眨眼或头发随机时间线。
- 连点保留前一阵的下落，最多三阵、最多 30 颗，过期自动清理。触发摸头、开始捏脸、关闭敲头、恢复默认、切换原表情或只看垫底时清理；金星在反应表情提前恢复后仍可落完，不改变静止立绘基线，也不参与鼠标命中。
- 摸头显示 `happy`，头绕脖子向有效水平移动方向轻倾，最大 ±2.5°、跟随缓动 0.08 秒；停手/松手约 0.25 秒回正，开心余韵 1.5 秒，再用 0.35 秒淡回。位移小于 2 个逻辑像素的抖动不续摸头。确认摸头立即清空连敲、解除委屈与金星。
- `Settings.expression` 始终是原选择，`Pose` 只承载当前反应与二级动作；同一时刻仅一个反应负责五官。捏脸按住时不被敲摸抢占；松手后可用敲摸接管，保留当前脸颊位移、速度、回弹倍率和二级姿态，旧反应不再复活。重新捏脸可接管敲摸，保留最初原表情及当前身体/手臂/头部姿态，包括整头下沉的连续过渡。
- 普通动画全关时仍可单独测试敲摸。失焦取消待判定点击并按松手结束摸头；关闭对应动作或恢复默认清理状态与连击。原表情选择在反应期间锁定；面板提供独立开关、阶段提示和折叠参数，每次反应锁定参数，新设置在下次反应生效。
- `--head-preview knock/combo/pat-left/pat-right` 与实际预览共用渲染器，`--time` 表示互动后的秒数，摸头截图场景在 1.2 秒松手；`--benchmark-head knock/pat` 与 `--benchmark-pinch` 互斥。操作与截图命令见 `v3proto/README.md`。真人手感、不同 DPI/缩放和真实窗口持续 FPS 仍需人工复验，不将离屏结果标记为最终验收通过。

### 独立拎起、拖动与回原位（2026-11-08，默认预览手感已验收）

## V3 正式接入（V3 第 2 步 S1–S9，2026-11-09～11-16，开发预览）

V3 纸偶渲染器接入真实桌宠窗口。**v3.0.0 起 V3 是唯一外观**：`python -m shion`（运行与 `--snapshot`）直接用 V3，没有 `--renderer` 选项（传了会被 argparse 拒绝），存档里也从来没有渲染器字段，不需要迁移。分支 `feature/v3-integrate`，未合并 master。

### 结构
- `shion/v3_window.py`：`V3PetWindow(PetWindow)`。`PetWindow`（`shion/pet_window.py`）只剩窗口骨架：窗口属性、信号、拖动（阈值 6px，阈内一律不算拖动）/慢放停留/快甩下落/落地/夹边、`set_height`、暂停标签、FPS 浮层、原地小跳（正弦 `LEGACY_JUMP_*`）；怎么画（`_load_sprites` / `_draw_sprite` / `_mask_for` / `_refresh` / `_sync_sleep_z`）是留给子类的接口，`PetWindow` 不能单独实例化。R2 已删除 V2 的贴图与帧序列、动作边界淡化、遮罩缓存、V2 手势分区（捏脸/肚子/摸头区）和 `TickleGesture`、`jump_sample` 及对应截图参数。窗口随机种子（截图/配图的固定 seed）同时决定发丝轻摆的时刻，同种子逐帧可重复。
- `shion/v3_display.py`：状态→表情映射 `STATE_EXPRESSIONS`、状态姿态 `STATE_POSES` / 周期动作 `StateMotion`、帧间隔 `frame_interval`、换边判断 `desired_side`、绘制量化键 `draw_key`。
- `shion/v3_layers.py`：两条渲染路径与待机头发间歇轻摆 `SwayEnvelope`。
- `shion/v3_prewarm.py`：眨眼开合度量化（0.05 一档，19 档）与后台预热线程。
- `shion/v3_memory.py`：窗口用 rig 的省内存处理（S7）。
- `v3proto/`：原型渲染核心（rig、头部表面、捏脸、反应脸、手势与动画），窗口只用它的公开入口；原型改动都保持默认行为不变。

### 尺寸与显示
- V3 可见身高对齐 V2 同档 idle（V2 不透明高度 480/512），窗口高度、脚底线与 V2 相同；纹理比例 = 显示高度 × DPR ÷ rig 可见高度，QImage 1:1 绘制。改尺寸/换屏 DPR 时重建或复用渲染器（每侧最多缓存 2 份）。
- 点穿遮罩外扩 4px，最多 10 次/秒更新；拎起中每帧重建；V2 帧（sx/sy/角度/跳）相对上次遮罩漂移 ≥3px 时提前重建。
- 气泡/菜单/面板按 V3 头顶锚点定位；吃零食碎屑用 `mouth_anchor()`（V3 为 rig 嘴部中心）。

### 渲染路径与帧节奏
- **仿射路径**：头发静止、无捏脸形变、无反应脸、无金星时，身体用 QPainter，头部用缓存帧整张平移/旋转。**网格路径**：其余情况（头发摆动、捏脸、拍/敲/挠/拎起反应、金星）。两路径同姿态平均差 <0.1/255。
- 待机头发间歇轻摆：每 6～12 秒一次、约 2.5 秒，0.6 秒淡入淡出；互动时立即满幅。
- 帧间隔：互动/程序动作/头发大幅摆动 16ms；睡眠类 66ms；头发静止的待机 66ms、工作 50ms；眨眼和轻摆开始前后、状态周期动作进行中 33ms；画面量化键不变时跳过重画。

### 手势（只用 V3 命中：cheek/crown/face/head/belly/body）
- **捏脸**：脸颊左右拉，`gesture("cheek_pull")` 只发一次、松手 `cheek_release`；10 秒内第 3 次起说 `cheek_pull_combo`。计数在 `shion/state.py` 状态机里，V2 窗口的捏脸同样适用（S7 验收确认保留）。
- **拎起（唯一挪窗口的方式）**：脸颊上相对按下点向上 >12 逻辑像素且竖向 >1.2×横向 → 真实移动窗口，复用 PetWindow 拖动/慢放停留/快甩或放到任务栏下落/落地压扁；台词 `cheek_lift`；来回 ≥24px 三次/2 秒晃晕。在脸颊以外拖动超过点击容差时窗口不动，发 `drag_ignored`，控制器 LOW 优先级说 `v3_lift_hint`（冷却 60 秒）；首次以 V3 启动约 10 秒后提示一次，说出后写存档 `v3_lift_hint_shown`（旧存档默认 False）。
- **摸头**：crown 区域来回摸，每 40px 发 `patted`（好感/统计照旧）。
- **敲头**：crown 单击，只播 V3 敲头动画，发 `knocked(bool)`（1.5 秒内第 3 下为抗议），**不算戳**、无好感/统计；台词 `head_knock` / `head_knock_stop`（LOW，4 秒类别冷却）。
- **挠痒**：肚子上来回揉，`gesture("tickle")` 开始并每 4 秒重复，停手 1 秒 `tickle_end`；肚子单击是普通戳（与 V2 不同，已告知用户）。
- 新台词键三语齐全：`cheek_pull_combo`、`cheek_lift`、`v3_lift_hint`；`head_knock`、`head_knock_stop` 已启用。

### 状态表现
- 表情：idle/working→neutral，neglect1→bored，slump→tired，happy/done/cheer→happy，proud→smug，stop→angry，dizzy→dizzy，neglect2→teary，yawn→yawn，collapse/sleep/bed/desk→sleep，drag→surprised。bored/tired/yawn 由 `tools/v3_s0_faces.py` 用 S0 部件拼成。
- 姿态（只用 Pose 已有字段；collapse / bed / desk 不走这里，见“姿势变体”）：working 头略低、每 4～6 秒轻点头，并抱着笔记本电脑（`Settings.arms='hold'`：`arms_hold` 整块代替两条手臂；手臂不动，捏脸挣扎/挠痒躲闪/拎起抬手都被忽略，身体、头、脸颊照常反应）；neglect1/2 低头；slump/collapse 下压低头；desk 低头；yawn 每 6～8 秒上抻；dizzy 头部画圈；喂零食点头咀嚼；stop 双臂略外抬（占位）。静态姿态 0.35 秒缓动，换状态不跳，互动期间整体淡出。V3 下关掉 V2 整图点头（`Animator.whole_nod`）。
- 抱电脑（S8）：`tools/v3_hold.py` 把 `assets/sprites/raw/v3/s6/working-hold.png` 按身体和腿拟合仿射对位，切出双臂加电脑整块为 `rig.json` 的 `arms_hold`（层级同手臂层，父级 body）。命中测试里它算 body：可戳、不触发挠痒；肚子挠痒只对电脑以外露出的肚子生效。
- 需新画素材清单与优先级见 `docs/v3-integration-plan.md`“需新画清单”。

### 姿势变体 scene（S9，2026-11-16）
- **做法**：collapse / bed / desk 三个状态各用一张画好的整图，不拆零件。`tools/v3_scene.py` 把图切成编号块、分出角色与家具像素，头部按站姿实测比例（`head_scale`：collapse 0.995、bed 0.877、desk 0.727）归一，写出 `assets/sprites/v3/scenes/`（图、角色遮罩、`scenes.json` 的尺寸、脚底线 `ground_y`、水平中心 `anchor_x`、头顶 / 嘴 / 睡觉 Z 锚点、摸头与拎起分区、呼吸增益）。scene 像素 ≈ rig 像素，脚底线对齐站姿脚底线，窗口 ← rig 换算原样可用。逻辑在 `shion/v3_scene.py`（纯逻辑，不依赖 Qt）、`shion/v3_scene_view.py`（图像与家具覆盖窗）、`shion/v3_window.py`（接入）。
- **分层**：under（垫底，只有家具颜色：角色像素里离家具不远的换成最近家具底色，即家具往角色底下延伸一圈，带宽 `seam_reach` 随离地高度变宽）→ char（只有角色，绕脚底支点做呼吸、摸头、敲头仿射）→ 家具层（点穿覆盖窗，盖在角色前面，去掉角色周围 `FURNITURE_GAP=2` 像素）。诗音窗口遮罩 = 变形后的角色 ∪ under 轮廓，家具不进遮罩所以点得穿。collapse 家具像素 <500，算没有家具，不建垫底和覆盖窗。
- **切换**：scene 之间、scene 与站姿之间**直接切换 + 小弹跳**（0.24 秒压到 0.97 再回弹），不做交叉淡化——两张轮廓不同的图淡化必然叠影（S9 真机验收改掉了原先 0.3 秒淡化的方案）。目标 scene 还在后台载入时先保持现在的画面，不卡界面；载入失败则丢掉该 scene，状态回到站姿回退。
- **互动**：拎起（拖动、下落、跳跃）立刻切回站姿；摸头整图倾斜 = 头部倾斜 ×0.4（≤1°）；敲头整图最多下压 2% 并带金星；V2 点击压扁只取 25%（最多压 2%）；捏脸、挠痒无反应（拖远了只提示“捏着脸往上提”）；家具点穿。头顶气泡锚点、嘴部碎屑锚点、bed 的睡觉 Z 都取 scene 自己的锚点。
- **窗口**：scene 比站姿宽时窗口临时加宽（脚不动），回站姿恢复；scene 显示期间冻结换边，回站姿停稳后再按原规则补换。
- **回退**：`SHION_V3_SCENES=0` 或 `scenes.json` 不存在时不用 scene，三个状态回到站姿 + 对应表情 / 姿态（collapse 下压低头、desk 低头、bed 睡）。
- **缓存**：后台线程按当前高度 × DPR 载入三个 scene 的数组（读图、缩放、预乘、垫底），主线程每帧最多收一个并转 QImage；缓存上限 `SCENE_CACHE=6`（三个 scene × 两种尺寸 / DPR）；没有后台任务时（缓存被挤掉）才同步载入单个。
- 右鼓脸型（S9 附带修复，`2f6d84d`）：下巴描线与新画鼓包描线衔接、清理眼睛用平滑填充而不是最近皮肤色、鼓包上缘描线保留。

### 换边（已实现，默认打开）
- 窗口中心在可用区域右半 → 左鼓，左半 → 右鼓，中线死区 max(5% 宽, 40px)；只在停稳 0.5 秒且无互动时判断，后台准备另一侧，在一次眨眼的闭眼帧切换并“啵”一下；旧侧闲置 5 分钟释放。`SHION_V3_AUTO_SIDE=0` 可固定左鼓。
- 启动按存档位置选侧（R1）：`app.run` 用存档里的窗口位置和各屏可用区域调 `v3_display.startup_side`（窗口宽按 `WINDOW_WIDTH_RATIO` 估算），把结果作为 `initial_side` 传给窗口，免得先建左侧再丢掉；估错无妨，首次显示 `_v3_side_startup` 仍按真实位置核对。丢掉一侧（启动纠正或 5 分钟释放）时，窗口记下那一侧还在跑的后台任务（`Prewarmer.close()` 返回），等它们结束且不在互动时补一次 `gc.collect()`（`v3_stats["gc_ms"]`）：被丢的 rig / 渲染器带引用环（`_locked()` 的闭包），不补就会一直占着内存（左半屏启动曾因此多 32MB）。
- 右鼓用画好的素材（S8，`assets/sprites/v3/right/`，`rig.json` 的 `right_side` 段，由 `tools/v3_right_plate.py` 从 `assets/sprites/raw/v3/s6/head-right-plate.png` 生成）：只有两块脸颊区（旧左脸颊处和新右鼓包处）以新画为准，区外与左侧逐像素相同。皮肤与描边进 `head_skin` / 干净底板 / 4 张睁眼底板，露出的鬓发进 `side_hair_l`（两者不重叠）；眼窗内不取新画的睁眼颜色，眼睛部件和刘海遮罩与左侧一致。捏脸运动沿用左侧公式按 `mirror_sum` 反射并整体下移 `dy`（新鼓包比镜像位置高）。`rig.json` 没有 `right_side` 时退回 S5a 的镜像逻辑（测试用）。

### 预热、缓存与内存（S7 版本）
- 后台单个低优先级守护线程，排序：当前表情睁眼帧与最深闭眼档、当前表情捏脸素材 → 其余表情睁眼帧 → 其余表情捏脸素材 → 反应脸补丁；当前表情的 19 档眨眼帧在不互动时每帧查缺补齐（被缓存淘汰的也会补回），互动时取消排队中的眨眼帧；失败的不重试。结果只在主线程写入缓存；淘汰时先不动当前表情的帧；预热未好时用最近已缓存档位。启动后约 10 秒做完。
- 主线程不等后台锁：已缓存的反应脸补丁直接取，不抢锁；这一帧要现算的东西（头部帧/捏脸素材/反应脸补丁）没缓存且锁正被后台占着时，本帧先保留上一帧画面，下一 tick 再画（`v3_stats["deferred"]` 计数）。
- 后台线程退出：`Prewarmer.shutdown_pool()` 取消排队任务、等正在跑的那一个（最多 1 秒）；挂在 `atexit` 和 `QApplication.aboutToQuit` 上，测试会话结束时也调一次。
- 每帧动画推进最多 0.25 秒（`MAX_DT`），隐藏或睡眠恢复后不逐子步追赶。右键/中键不打断进行中的左键手势。
- 缓存上限：头部帧 64、仿射用 QImage 8、头发位移场每缕 24（float32）、反应脸补丁 40、反应脸遮罩 8、捏脸眨眼保护 32。
- 窗口用 rig 经 `compact_rig`：整画布稀疏遮罩（各表情捏脸保护遮罩、两张刘海遮罩、pink_cleanup）只存有内容的一块（`SparseCanvas`，crop 结果逐像素相同），有 face_plate 时释放用不到的 face_contour。
- 工具：`python -m tools.v3_mem`（离屏或真实窗口的分项字节数与进程工作集；S9 起含 `scenes` 一节，`--load-bench N` 测同步载入单个 scene 的耗时，`SHION_V3_SCENES=0` 时文件名带 `-noscene`）；`python -m tools.v3_perf`（真实窗口 FPS/CPU，`--warmup 20` 排除启动预热；S9 起支持 `state:<名>+knock|pat` 与 `switch` 场景，结果含 `refresh_max_ms`、`scene_load_ms`）。

### 性能与内存验收线
- 互动场景 DPR1.5：160/200 平均 ≥55 FPS、计算+绘制 P95 ≤14ms；260/320 ≥50 FPS、P95 ≤20ms。
- 待机：总 CPU ≤3% 且单核不超过 V2 同档待机的 2 倍；工作：总 CPU ≤3% 且单核不超过 V2 同尺寸同 DPR 的待机单核。CPU 需与 V2 在同一时段测，并等预热做完（`--warmup 20`）。
- 内存（R1，2026-11-17 修订）：真实应用总工作集（启动后 25 秒，DPR1.5）：**默认高度 200 ≤260MB**，左半屏与右半屏启动相差 ≤5MB。原 S7 的“230MB”线作废：S7 记的 223MB 是 199/197/247/251 两档的平均，今天用同法重测 S7 末源码稳定在 253MB（波动 ±2MB），V2 为 185MB。R1 实测（修复后）：200 高 254.8MB（右半屏启动）/ 255.8MB（左半屏启动，修复前 289MB、峰值 304MB），260 高约 271MB，320 高约 290MB。**这条线只适用于默认高度 200**；260 / 320 高只记录实测数字、不设线（用户 2026-11-17 决定：超就超，不再压）。大头：`import scipy.ndimage`（连带 linalg / sparse / special）约 +27～41MB，单侧 rig 保留约 28MB、渲染器约 17MB。
- S9 实测（2026-11-16，DPR1.5，数据在 `build/v3/integrate/s9/`，不入库）：三个 scene 的图像合计 260@1.5 约 3.5MB；scene 静置总 CPU 0.26–0.38%，单核低于站姿回退；scene 内敲头 / 摸头 P95 ≤18.8ms；idle/bed/desk/collapse 每秒轮换最长一帧 ≤35ms。**已知限制（用户决定记录不处理）**：①真实应用总工作集约 254MB（3 轮平均，scene 开 253MB / 关 255MB，V2 约 185MB），超过 230MB 线，与 scene 无关，S7 之后涨起来的；②缓存被挤掉后同步载入单个 scene 约 250～280ms（目标 ≤80ms），真实运行中三个 scene 启动后由后台载入、从未触发同步载入；③desk 摸头在量化键不变时少画帧，合成测试 28.5 FPS（P95 11.6ms），未在真实窗口逐帧确认。
