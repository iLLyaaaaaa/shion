# Shion（诗音）完整规格

> 中文名诗音，日文名詩音（しおん），英文名 Shion。她在台词里会用这个名字称呼自己。
> 非官方粉丝作品，与 Anthropic 无关。

## 技术栈

- Python 3.10+，GUI 用 **PySide6**
- 虚拟环境：`.venv`（`python -m venv .venv`，然后 `.venv\Scripts\pip install -r requirements.txt`）
- 依赖尽量少：`PySide6`、`pytest`；`numpy`、`scipy`、`pillow` 只给素材脚本用。hook 脚本**只能用标准库**。

## 素材

`assets/sprites/` 里有 12 张状态图和可选的 16 张动作帧（walk 8、jump 4、drag 4），是 Q 版 2.3 头身，尺寸统一为 448x512（人物高约 480，头约占上部 45%，脚底离底边 8px），**画框和脚底基线已对齐**，切换时不需要任何偏移。

处理脚本 `tools/process_sprites.py`：不依赖固定坐标，把 `raw/` 的原图清理 alpha 去毛边；以 idle 为基准把站立图的人物高度统一到 480，坐着/悬空的图（sleep/drag/neglect2）用站立图的平均缩放比例；脚底贴底，水平按头部（上部 40%）重心居中，切换表情时头不跳；个别图用 `EXTRA_SCALE` 手动微调。

`tools/process_sheets.py` 单独处理 `raw/walk_sheet.png`、`raw/jump_sheet.png`、`raw/drag_sheet.png`，生成 `walk_1~8.png`、`jump_1~4.png`、`drag_1~4.png`，包含预期帧数检查与粘连帧自动拆分；普通状态脚本跳过 `*_sheet`。运行时三种动作组都按实际文件的数字编号排序，支持任意帧数：必须从 1 到实际最大编号连续、全部可解码且与 idle 同画布，才整组启用；不满足时各组独立回退。没有额外清单声明尾帧数量，故完整的较短连续组也有效；素材脚本的 EXPECTED 只检查当前三张源图。

| 文件 | 用途 |
|---|---|
| idle | 默认站立 |
| blink | 眨眼帧（只有眼睛和 idle 不同） |
| happy | 被摸头 |
| proud | 叉腰得意（被夸 / 连续完成任务） |
| stop | 伸手挡住、脸红（戳太多次，傲娇） |
| dizzy | 蚊香眼（戳到爆 / Claude 出错） |
| working | 抱着电脑打字（Claude 正在干活） |
| done | 抱着电脑闭眼笑（Claude 刚完成任务） |
| sleep | 坐着打瞌睡，图里自带 zzz |
| drag | 被拎起来乱扑腾 |
| neglect1 | 落寞发呆（冷落 1 级） |
| neglect2 | 蜷膝泪笑（冷落 2 级） |

配色（从原图取样）：黑 `#0A0A0A`、米白 `#FCF2E6`、橙 `#F58236`。

## 窗口

- 无边框、背景透明、始终置顶、不在任务栏显示：`FramelessWindowHint | WindowStaysOnTopHint | Tool`，加上 `WA_TranslucentBackground`。
- 默认显示高度 **200px**（图片按比例缩放，用平滑缩放）。右键菜单可以调成 160 / 200 / 260 / 320。
- 默认位置：主屏幕可用区域（`availableGeometry`，不含任务栏）的右下角，脚底贴着底边。
- 透明像素要能**点击穿透**。Windows 的分层窗口一般会自动穿透，务必实测确认。如果不行，用 `setMask` 根据当前帧的 alpha 生成遮罩。
- 只允许运行一个实例：用 `QLocalServer`/`QLocalSocket` 检测，第二个实例启动后直接退出。

## 交互

| 操作 | 判定 | 反应 |
|---|---|---|
| 鼠标悬停在头部 | 精灵图上方 45% 的区域 | 光标变成张开的手（`Qt.OpenHandCursor`） |
| **摸头** | 在头部按住左键并左右移动，累计移动超过 40px 算摸 1 次 | happy、好感度 +1、爱心；不产生待表扬记录。新摸头过程首次反馈立即冒 2 颗，后续爱心间隔 ≥0.2 秒、同时 ≤6 颗，约 20px、上飘 55px，超额忽略不排队 |
| 单击身体 | 按下到松开，移动不超过 6px | 轻微压扁再弹回（0.2s），随机说一句话 |
| 连续戳 | 相邻点击间隔 ≤1.5 秒，超时从第 1 下重算 | 1～2 下只压扁＋台词；3～4 下 stop 60% / dizzy 20% / 普通 20%；第 5 下起 stop 55% / dizzy 40% / 普通 5%。每次只抽一次，互斥；挡手或晕后清零。stop 2 秒、戳晕 3 秒 |
| **拖动** | 在身体上按住并移动超过 6px | 切到 drag，窗口跟着鼠标走，保留速度倾斜并循环拖动帧；默认 110ms/帧，越快、晃动越多越快，最快 60ms/帧；松手下落继续播放，落地才恢复表情。缺图回退静态 drag.png |
| 拎起晃动 | 水平方向反转，反向摆幅 >40px 确认一次；任意 2 秒内至少 3 次 | 记住晃晕直到落地，下落仍是 drag；落地后 dizzy 2.5 秒并说 dizzy 台词。小幅抖动、一直向同侧移动不计数，每轮拖动独立 |
| 松手 | — | 带重力下落到脚底贴住屏幕可用区域的底边（不能越出屏幕），落地时压扁一下；恢复固定/自动状态，达到晃晕阈值时先显示 dizzy 2.5 秒（固定表情仍优先） |
| 双击 | — | 气泡显示状态：已陪伴多久、今天被摸了几次、Claude 今天完成了几个任务 |
| 右键 | — | 工作遥控（暂停/继续 ／ 做得好 ／ 有问题……）／ 表情 ／ 活跃度 ／ 动作 ／ 大小 ／ 静音气泡 ／ 只显示状态，不显示内容 ／ 语言 ／ 开机自启（v1.0）／ 关于 ／ 退出 |

- **工作遥控**（见 v0.3）：“做得好”好感度 +3、proud，并加入反馈队列；“有问题……”弹出一行输入框（可留空）；“暂停工作/继续工作”按当前状态二选一。
- **表情**：开心 happy、得意 proud、害羞挡手 stop、晕乎乎 dizzy、工作中 working、完成啦 done、睡觉 sleep、发呆 idle、委屈 neglect2；不提供 blink、drag、neglect1。默认临时显示 5 秒；勾选“固定当前表情”后保存并保持，之后选新表情仍固定；“恢复自动”解除。固定期间台词、统计、Claude 状态照常处理；拖动/下落仍为 drag，落地恢复固定表情。双击状态显示“表情已固定”。
- **活跃度**：安静 / 普通（默认）/ 活泼，写入存档。普通每 8～20 秒、活泼每 4～10 秒随机做一件原地动作：镜像转身、镜像朝向鼠标、原地小跳（与菜单跳跃共用下述帧动画）、开心或发呆 2 秒、自言自语 `idle_talk`（10% 抽取概率、至少间隔 60 秒）。安静关闭待机动作；Claude 实际工作中、表情固定、睡着、拖动/下落、按住鼠标或打开菜单期间暂停，恢复后重新等待、不补播。自动动作不刷新睡眠/被理会时间。
- **动作**：散步一会儿（沿当前屏幕任务栏上沿随机走 10 秒）、走到屏幕另一边（当前屏幕对侧）、跳一跳、转个身。步速 60px/s，两种行走均循环 `walk_1~8`，向右用原图、向左镜像；60px/s 时每帧 110ms，帧时长 = 基准帧时长 × 参考速度 / 当前速度，三者在 behavior.py 中可调。每两帧一步同步起伏 3px，每步落地轻微压扁约 3% 后回弹，时长跟随步频。缺图时保留原状态图＋10px / 0.45 秒起伏。边界限制精灵在屏内；左键按下立即中断，随后照常戳/摸/拖。走完或中断保存新位置；跳和转身最终位置不变。
- **跳跃**：菜单、待机和计划提醒共用 `jump_1` 下蹲 0.15 秒 → `jump_2` 上升 0.09 秒 → `jump_3` 最高点停顿 0.2 秒 → `jump_4` 下落 0.11 秒。上升三次 ease-out，最高 45px；下落二次加速。下蹲约 10% 压缩；0.55 秒恢复当前状态图，落地最低 sy=0.84、压扁回弹 0.25 秒。未来替换其他帧数时，按四阶段的归一化进度映射全部帧，阶段时长与高度曲线保持不变。无有效帧组时回退原来的 18px / 0.5 秒原地跳。
- **拖动帧速率**：二维移动速度 / 800px/s 与 2 秒内有效反转数 / 3 两者取较大值，夹在 0～1；目标帧时长从 110ms 线性减到 60ms，帧速率用 0.08 秒指数缓动并解析积分累计相位，变速不重置帧。松手保持当时的实际帧速率，下落及重新抓住时相位连续；晃晕判定、固定表情优先级沿用原规则。速度、时长与缓动参数集中为常量。
- 上述概率、次数、时间、距离集中在 `state.Config`、`behavior.py`、`effects.py`、`speech.py` 的常量中，便于调节。

## 程序动画（animator.py）

- **呼吸**：idle、neglect1 状态下，纵向缩放在 1.000 和 1.012 之间正弦变化，周期 3 秒，以脚底为锚点。
- **眨眼**：idle 状态下每隔 3～6 秒（随机）切到 blink 120ms；有 15% 的概率连续眨两次。
- 所有缩放、倾斜都以**脚底中心**为锚点，避免人物飘起来。
- 动画计时器用 `Qt.PreciseTimer`；桌宠、气泡、粒子按 `time.perf_counter()` 的实际经过时间计算，掉帧后直接到达对应时刻；下落使用重力位置解析式，不截断经过时间。
- 切换精灵使用约 120ms 的 ease-out 交叉淡化，附带约 3% 的压扁和轻微回弹；快速切换时从当前混合画面接续，缩放、角度也从当前姿态缓动，脚底锚点保持固定。眨眼的淡化不附加压扁。
- 动作序列在显示层覆盖底层表情，序列内部直接按经过时间取帧，不对每一帧做状态淡化。结束或中断后恢复当前底层状态；绘制与遮罩使用同一动作帧和位移，掉帧不拖慢动作。落地回弹以预定落地时刻计时。
- 粒子位移使用三次 ease-out，拖动倾斜使用指数 ease-out，压扁使用先压缩后回弹的平滑曲线；鼠标拖动位置仍直接跟随用户输入，下落保持非线性重力加速。
- 待机动作由独立行为调度器控制，替代原来的 6～15 秒歪头/左右晃。Claude 工作中、固定表情、睡眠和安静档只保留适用的呼吸/眨眼，关闭摆动；独立 blink 图仅用于 idle，不替换其他固定表情。镜像缓存运行时图像，不修改精灵素材；绘制和遮罩共用脚底锚点与镜像结果，跳跃同步更新遮罩。路径按实际经过时间采样，掉帧不减慢行走。
- 遮罩按量化后的姿态缓存，淡化时取两张图的可见区域并集；仅透明度变化时复用遮罩。每次只绘制一遍，再平移合并区域扩边。

## 状态机（state.py）

优先级从高到低（高优先级的临时状态结束后，回到底层状态）：

1. **drag**：正在被拖动
2. **固定表情 / 手动表情**：固定无期限；未固定的手动表情 5 秒
3. **临时反应**（有持续时间）：happy、stop、dizzy、done（3 秒）、proud（3 秒）
4. **working**：收到 Claude 开始干活的事件；收到 stop / plan_ready 事件或 2 分钟没有新事件后退出。plan_ready 只提醒看计划，不计为完成任务、不触发 done 或完成后的定时催促
5. **sleep**：本地时间 0:30～6:30，或者 15 分钟没有任何鼠标交互、也没有 Claude 事件。任何交互都会唤醒，唤醒时说一句起床台词
6. **待机短暂表情**：happy / idle 2 秒
7. **底层状态**：根据冷落值决定
   - 距离上次“被理会”（摸头、点击、或任意 Claude 事件）**< 30 分钟** → idle
   - **30 分钟～2 小时** → neglect1
   - **> 2 小时** → neglect2
   - 从 neglect2 回到 idle 时，说一句特别的台词（例：`> ……你终于回来了。`）
   - 阈值写在配置里，方便调整

好感度：整数，只增不减（摸头 +1，做得好 +3，吃完零食 +2），目前只在双击状态里显示，后续可以用来解锁台词。预设对话不增加好感度或摸头统计。

## 持久化

`%APPDATA%\Shion\state.json`（用 `QStandardPaths.AppDataLocation` 获取）：

```json
{
  "schema_version": 4,
  "first_run": "2026-10-19T20:00:00",
  "affection": 0,
  "last_attended": "ISO 时间",
  "feedback_queue": [{"kind": "good", "text": ""}],
  "remote": {"pause_timeout": 1800, "permission_timeout": 120},
  "stats": {"date": "2026-10-19", "pats": 0, "claude_tasks": 0},
  "window": {"x": 0, "y": 0, "height": 200},
  "bubble_muted": false,
  "inject_praise": true,
  "language": "zh",
  "privacy_mode": false,
  "fixed_expression": null,
  "activity_level": "normal",
  "snacks": {"date": "2026-10-19", "count": 0}
}
```

状态变化后延迟 2 秒写盘（防抖），退出时立即写。写文件时先写临时文件再替换，防止写到一半损坏。
旧存档没有 `schema_version` 时按 v1 处理：因无法分辨待表扬来自摸头还是菜单，升级丢弃旧 `pending_praise`，其余数据保留；v2 的 `pending_praise`（都来自菜单）迁移成反馈队列里等量的“做得好”（最多 5 条）；v3 起不再写 `pending_praise`。`feedback_queue` 最多 5 条，每条 `kind` 为 `good`/`bad`，`text` 单行最多 200 字；`remote` 的秒数会被限制在安全范围内（暂停 60～1880，授权 10～170），hook 脚本直接读它。缺失/非法的表情和活跃度恢复默认值。

v4 新增独立 `snacks` 统计：本地日期和当天成功吃完的次数（0～5），缺失/非法次数默认 0，跨日清零；重启不清零。旧档保留其他数据。正在吃东西和菜单触发的睡眠不持久化。

## 对话气泡（bubble.py）

- 独立的无边框置顶小窗口，跟随在桌宠头顶上方；如果靠近屏幕边缘，自动翻到另一侧。
- **终端风格**：背景 `#0A0A0A`，1px 橙色 `#F58236` 边框，圆角 4px，米白色文字，等宽字体（优先 `Cascadia Mono`，回退到 `Consolas`），每行开头加 `> `。
- 打字机效果：每 30ms 出一个字，全部显示完后停留 4 秒再淡出（0.3 秒）。
- 台词统一经控制器仲裁：高优先级（完成提醒、计划写好提醒、出错、催促、等待确认和授权请求）随时打断；中优先级（问候、唤醒/回归、菜单反馈、双击状态查询）只能打断低优先级；低优先级（摸头、戳、拖、自言自语、工作过程提示）不能打断中/高。当前气泡自然消失后不再阻挡。
- 低优先级互相替换时，当前气泡须已出现至少 2.5 秒（从气泡开始出现计时，不从打字完成计时），且同一触发类别已实际说出的台词至少间隔 4 秒；戳导致的普通/挡手/晕共用戳冷却，拖动及其落地晃晕共用拖冷却。被拦截的台词丢弃，不补播，不消耗随机台词选择。
- 相邻摸头间隔 ≤1 秒算同一过程：开始尝试说一句，连续持续超过 6 秒再尝试一句，同一过程最多两句；仍受低优先级规则限制。每次摸头的爱心、表情、好感度及统计照常。相关时间都在 `speech.py`。
- 台词从当前语言的 json 随机抽取，同一类台词不要连续重复。静音时不弹气泡。
- 气泡字体：首选等宽字体不变，后面追加当前语言 `meta.font_fallback` 里已安装的字体（日文、中文字符走它）。

### 多语言（lines.py）

- 语言文件 `assets/lines/<代码>.json`，格式：`meta`（`name` 是该语言自己的名字，显示在菜单里；`font_fallback` 是字体备选列表）、`lines`（台词类别 → 台词数组）、`ui`（界面文字，`{xxx}` 是占位符，如 `{version}`、`{span}`、`{port}`）。
- **语言列表自动扫描**该目录下所有能解析的 `*.json`（坏文件跳过），中文排第一，其余按代码排序。新增语言只需放一个 json，不用改代码。
- **回退**：缺的台词类别、缺的界面文字都回退到中文（`zh.json` 必须完整）；`ui()` 在占位符对不上时不抛异常；语言文件不存在就用中文。
- **首次启动**（存档里没有 `language`）跟随系统语言（`QLocale`）：`zh*` → 中文，`ja*` → 日文，其他 → 英文；结果写入存档，之后固定。

## 本地通信协议（server.py）

- 监听 **`127.0.0.1:47613`**，只绑定本机。用标准库 `http.server` 在后台线程运行，通过 Qt 信号把事件转发给 GUI 线程，**不能在后台线程里直接操作界面**。
- `POST /event`，请求体为 `{"type": "...", "detail": "可选"}`

| type | 来源 | 桌宠行为 |
|---|---|---|
| `session_start` | SessionStart hook | 说一句问候，刷新“被理会”时间 |
| `prompt` | UserPromptSubmit hook | 刷新“被理会”时间 |
| `working` | PreToolUse hook | 进入 working（已经在 working 时忽略） |
| `stop` | Stop hook | 退出 working → 播放 done 3 秒 + claude_done 台词，claude_tasks +1 |
| `plan_ready` | ExitPlanMode 的 PermissionRequest hook | 高优先级气泡“计划写好啦，去看看吧～”并跳一下；退出 working，不弹授权面板、不计完成任务 |
| `notification` | Notification hook | 气泡提示“有事情等你确认哦”（只有终端版会触发） |
| `react` | 预留（目前没有调用方） | `detail` 是表情名，临时切换到该表情 3 秒 |

- `POST /feedback/take` → 返回 `{"text": "…"}`：取走并清空反馈队列，按存档语言合成要注入的文字（没有则为空串；`inject_praise` 为 false 时仍清空但返回空串）。读取和清空是同一个原子操作
- `POST /pause/wait {"wait": 秒}` → `{"paused": true|false}`：没暂停立即返回；暂停中最多等 `wait` 秒（上限 30）。**只读，没有任何接口能让 HTTP 调用方开始暂停**；`prompt` 事件到达时服务线程会直接解除暂停
- `POST /permission/open {"tool", "detail"}` → `{"id"}`（请求体上限放宽到 64 KB；排队上限 20，满了返回 503）；`POST /permission/wait {"id", "wait"}` → `{"id", "status"}`，`status` 是 `pending`/`allow`/`deny`/`gone`，`allow`/`deny` 只能取一次；`POST /permission/withdraw {"id"}` 撤回。**没有任何接口、任何字段能写入 allow/deny**，决定只来自诗音界面上的按钮（有测试往所有接口和事件类型里塞各种“同意”字段，请求始终保持 pending；另有源码级测试保证只有 controller 的按钮回调会写入决定）
- `type = pause_timeout`（hook 等满暂停上限后发来）：诗音保持暂停标记，把气泡换成“已经停下了，在 CC 里说一声就能继续”
- `GET /health` → `{"ok": true}`
- 安全：带 `Origin` 头的请求（来自网页）和 `Host` 不是 `127.0.0.1` / `localhost` 的请求一律返回 403，不触发任何回调；读请求体有 5 秒超时。hook 脚本是普通 HTTP 客户端，不受影响。

## Claude Code hooks（v0.2）

`hooks/shion_hook.py <事件名>`：

- 只用标准库（`urllib.request`），**超时 0.5 秒**。桌宠没运行或请求失败时**静默退出、返回码为 0**，绝不能影响 Claude Code 的正常使用。
- 从 stdin 读取 hook 输入的 JSON（可以不用，但必须读完）。
- `UserPromptSubmit`：先发送 `prompt` 事件，再调用 `/feedback/take`；返回的文字非空就原样打印到 stdout（`[诗音] 用户觉得你刚才做得很好。` 等，按存档语言使用中/英/日；多次“做得好”合成一句，不写次数；摸头不产生反馈）
- `PostToolUse`：调用 `/feedback/take`，非空则输出 `hookSpecificOutput.additionalContext`（Claude 工作中即可收到反馈）
- `PreToolUse`：先问 `/pause/wait`；暂停中就按 25 秒一段一直等，直到继续或 `prompt` 解除；诗音没开、连不上、返回内容不对一律放行；等满暂停上限（默认 30 分钟）输出 `permissionDecision: deny`（理由“用户暂停了工作，请停下并等待用户指示”）并发 `pause_timeout`
- `SessionStart`：如果 `/health` 不通，就启动桌宠（`.venv\Scripts\pythonw.exe -m shion`，脱离父进程，不弹出控制台窗口），然后发送 `session_start` 事件。
- `Stop`：只发送 `{"type":"stop"}`，不读取/转发 `last_assistant_message`，不打开 `transcript_path`。只说当前语言的完成提醒。
- 其他事件（`PreToolUse` 发 `working`、`Notification`）只负责转发。
- 配置写进**用户级** `~/.claude/settings.json` 的 `hooks` 字段，这样终端和桌面端的 Code 标签页都会加载。写之前先备份原文件，**合并而不是覆盖**用户已有的配置。另外写一个 `tools/install_hooks.py`（安装）和 `tools/uninstall_hooks.py`（卸载）。

## 状态感知（v0.2.1）

让诗音知道 Claude Code 正在干什么，当好状态窗口，也是 v0.3 遥控功能的“眼睛”。全部基于 hooks，只读，不打扰工作。

- **完成提醒**：Stop 只提示去看结果，中文如“做完啦！去看看结果吧～”；英文如“All done! Take a look at the results~”；日文如“終わったよ！結果を見てみてね～”。三语均有原生台词，不显示回复第一句；旧 hook 发来的 stop detail 也不显示、不记录到最近活动或控制器日志。最近活动只显示“做完了”。done 表情、任务计数和定时催促保留
- **计划提醒**：ExitPlanMode 的 PermissionRequest 仅发送无 detail 的 `plan_ready` 事件，计划正文不发送。三语分别是“计划写好啦，去看看吧～” / “The plan's ready! Take a look~” / “計画ができたよ、見てみてね～”。高优先级可打断已有气泡，同时复用菜单原地跳跃一次（静音只抑制气泡，仍跳；拖动/下落时沿用跳跃的保护，不强行中断）。不登记授权、不轮询、不输出 allow/deny，确认由 CC 自己处理
- **显示正在干什么**：PreToolUse 时根据工具名和参数生成简短描述，例如“在读 state.py……”“在跑命令……”“在改 bubble.py……”。同一个描述 3 秒内不重复弹出
- **出错反应**：工具执行失败时（PostToolUse 结果里带错误，或官方提供的失败事件），切到 dizzy 2 秒，说一句“呜……出错了”
- **催你回来**：Claude 停下后，如果 5 分钟（可配置）没有新的 UserPromptSubmit，诗音跳一下提醒；最多提醒 2 次
- **最近活动记录**：内存里保留最近 20 条事件（时间、类型、简短描述），双击状态里可以看最近 5 条；不写入存档
- **隐私开关**（右键菜单）：“只显示状态，不显示内容”。打开后不显示文件名、命令；回复内容无论开关状态都不显示

## Claude Code 遥控（v0.3）

诗音成为 Claude Code 的遥控器。**只用官方 hooks 机制，不模拟按键，不往对话里发消息。** 界面文字里不出现“Claude”（见 v1.0「名称与品牌」），统一叫“工作”。

右键菜单新增“工作遥控”子菜单；需要用户决定时，诗音会主动弹出带按钮的气泡。

| 操作 | 实现 | 行为 |
|---|---|---|
| **同意 / 否决** | **PermissionRequest hook**：返回 `hookSpecificOutput.decision.behavior` 为 `allow` / `deny`（字段按官方文档确认）。hook 脚本向本地服务器长轮询，等待用户在诗音上的选择 | 气泡显示要执行的命令或要改的文件（完整显示，过长时可展开）和两个大按钮。**ExitPlanMode 例外，只提醒，计划确认由 CC 自己处理** |
| **做得好 / 有问题** | 放进**反馈队列**；送达方式见下 | “有问题”可以附一句话（单行输入框，可留空） |
| **暂停 / 继续** | **PreToolUse hook**：暂停期间 hook 长轮询等待，不返回 | 见下面「暂停规则」 |

**同意 / 否决的安全规则**
- 决定**只能由用户在诗音界面上亲手点击产生**。本地 HTTP 服务**不提供**任何“设置决定”的接口，hook 只能“等待结果”
- 默认等待 **120 秒**（可配置）。超时后 hook 不给决定，CC 照常弹出自己的授权框。**任何情况下都不能默认同意**
- 诗音没在运行、连不上服务器时，hook 立刻退出、不给决定，交回 CC 自己处理
- ExitPlanMode 无论有无计划、计划多长，一律不登记请求、不给决定；只尝试发送 `plan_ready`，发送失败也静默退出
- 同一时间可能有多个授权请求（例如子代理并行）：按顺序排队，一次只显示一个，显示“还有 N 个”
- 否决时附带理由“用户通过诗音否决了这个操作”
- 内容超过 12000 字（面板放不下、用户看不全）时，hook 不登记请求、不给决定，交回 CC 自己的授权框
- 威胁模型：只防网页（Origin/Host 检查）和“hook 出错/超时/诗音没开”；**不防本机已被攻破的恶意进程**（本机 HTTP 无认证：它可以占着 47613 冒充诗音、灌满排队造成拒绝服务、发 prompt 事件解除暂停），这类问题不在本版范围

**反馈队列（做得好 / 有问题）**
- 内容示例：`[诗音] 用户觉得你刚才做得很好。` / `[诗音] 用户认为刚才的改动有问题：<用户输入的话>。请重新检查。` 不加“请回复”之类的话
- 送达（只用附加上下文，不产生聊天消息）：
  - Claude 正在工作：下一次 **PostToolUse** 的 `additionalContext`（官方说明：放在工具结果旁边，Claude 下一轮会读到，不作为聊天消息显示）
  - Claude 空闲：下一次 **UserPromptSubmit** 时附加
- 多条合并成一次送达；队列最多 5 条；送达后诗音说一句“已经转告啦”
- 右键原有的“夸夸”菜单项并入“工作遥控 → 做得好”；原来的 `pending_praise` / `/praise/take` 已由反馈队列和 `/feedback/take` 取代（存档迁移见「持久化」）

**同意 / 否决的实现要点（v0.3 第二部分）**
- hook（PermissionRequest）：`AskUserQuestion` 不处理（那是提问不是授权）；`ExitPlanMode` 只向 `/event` 发 `{"type":"plan_ready"}`，不进入授权流程；其余工具先 `/permission/open`，再按 10 秒一段 `/permission/wait`。**只有响应是对象、`id` 对得上、`status` 恰好等于 `"allow"` 才输出 allow**；`"deny"` 输出 deny + 存档语言的理由（`ui.hook_deny`，默认“用户通过诗音否决了这个操作”）；其余一切（连不上、超时、`gone`、字段不对）都不输出任何决定。超时（存档 `remote.permission_timeout`，默认 120 秒）先撤回请求再退出。
- 显示的内容：Bash/PowerShell 显示命令（有描述则附 `# 描述`）；Edit/Write/NotebookEdit 显示文件完整路径；WebFetch 显示网址；WebSearch 显示搜索词；其他显示参数 JSON（不含已排除的 ExitPlanMode / AskUserQuestion）。最多 12000 字。**隐私模式不影响授权面板**（要决定就必须看到内容）。
- 面板（`panel.py:PermissionPanel`）：终端配色；内容区只读、约 6 行高，过长出现“展开/收起”；“还有 N 个”；“否决”“同意”两个大按钮。**不抢焦点、不响应键盘**（`WindowDoesNotAcceptFocus`，按钮子类忽略所有按键），按钮在每条请求出现后 0.6 秒内不可点。静音不影响面板，只影响那一句提示语。
- 排队：诗音每 100 毫秒从 hub 取最早的未决请求显示；hook 超过 25 秒没来轮询的请求视为已被 CC 取消（用户在 CC 里自己答了），面板自动消失。
- 服务端 `request_queue_size` 调到 64，并行子代理的 hook 同时连进来不会被重置。

**暂停规则**
- 点“暂停”后，Claude 在**下一次调用工具之前**停住（PreToolUse hook 等待）。正在执行的命令不会被掐断；正在写的文字会写完。诗音切到暂停状态，气泡显示“暂停中”
- 恢复方式有两种：
  1. 在诗音上点“继续”：hook 立即放行，Claude 无缝接着干
  2. 在 CC 里直接对 Claude 说话：任何一次 **UserPromptSubmit** 都会自动解除暂停
- **超时（默认 30 分钟，可配置）**：hook 返回 `deny`，理由写“用户暂停了工作，请停下并等待用户指示”，Claude 结束这一轮。此时诗音提示“已经停下了，在 CC 里说一声就能继续”。之后在诗音上点“继续”只解除暂停标记，无法替用户发消息
- 诗音没在运行、连不上服务器时，hook 立刻放行，不会把 CC 卡住
- 子代理的工具调用同样受暂停影响

**hooks 配置**
- PermissionRequest、PreToolUse 的 hook 超时要设得比上面的等待时间长（例如 PermissionRequest 180 秒、PreToolUse 1900 秒），由 hook 脚本自己控制提前返回
- 实现后要在 CC 终端版和桌面端 Code 标签页里实测：授权请求能否被诗音接管、暂停时 CC 界面显示什么。结果记录到 progress.md

## 内容包（v0.5）

类似创意工坊：别人做好内容包发到 GitHub，其他人下载就能用。

- **只允许数据，不允许代码**：内容包里只能有 PNG 和 json。加载时只解析这两类文件，忽略其他一切文件；解压时防止路径穿越（`../`）和超大文件（单个文件、总大小都设上限）
- **类型**（一个包可以包含多种）：
  - 角色包：精灵图（同 `assets/sprites/` 的 12 个状态，缺的用最接近的状态代替）+ 该角色的台词
  - 台词包：新增或覆盖某个角色、某种语言的台词
  - 零食包、对话包：给 v0.4 的菜单新增选项
- **格式**：`manifest.json`（`id`、`name`、`version`、`author`、`license`、`types`、`min_shion_version`、各语言的名字和简介）+ 按类型分的子目录。诗音自带的内容也做成一个默认包
- **安装**：把 `.zip` 拖到诗音身上，或右键“导入内容包”；安装前显示名称、作者、许可证让用户确认。安装到 `%APPDATA%\Shion\packs\`
- **管理**：右键“角色”切换当前角色；“内容包”里勾选启用、查看详情、删除
- **给制作者**：模板仓库（带说明的空白包）；`tools/validate_pack.py` 检查尺寸、透明度、json 格式、缺失状态并给出具体报错；素材处理脚本改成能处理任意角色
- 社区索引（`shion-packs` 仓库 + 应用内浏览）暂不做，等有人做了内容包再说

## 可测试性要求（重要）

CC 看不到屏幕，所以设计上必须让大部分东西能**不靠人眼**验证：

- **状态机是纯 Python**：`state.py` 不能 import Qt。时间通过参数传入（例如 `now: datetime`），不能在内部直接调用 `datetime.now()`，这样“2 小时后进入冷落”可以在测试里瞬间模拟。
- 测试用 `pytest`，放在 `tests/` 下。运行方式：`.venv\Scripts\python -m pytest -q`，只看失败的输出。
- **调试截图模式**：`python -m shion --snapshot out.png [--state happy] [--bubble "文字"]`，离屏渲染一帧存成 PNG 后退出。`--from-state idle --state happy --at 0.06` 可检查淡化中间帧；不传 `--from-state` 时直接显示目标状态。CC 需要检查画面时，生成截图再打开看，**只看截图，不要打开 assets 里的原始素材**。
- 截图追加 `--mirror` 检查水平镜像；`--walk --at 0/0.11/…/0.77` 检查八帧；`--jump --at 0/0.15/0.24/0.44` 检查四阶段（0.24～0.44 秒最高点，0.55 秒落地）；`--drag --at 0/0.11/0.22/0.33` 检查拖动四帧，可与状态/三语气泡参数组合。三个动作参数互斥。截图不创建 FPS 窗口，也不计入实际绘制次数。
- 截图 `--panel permission|input [--panel-text 内容] [--panel-more N] [--panel-expand] [--lang ja]` 只画遥控面板。
- 截图 `--panel dialogue|snacks|eating [--lang zh|en|ja]` 检查对话首页、零食页或 happy 与碎屑效果；只查看此入口生成的截图，不打开精灵原图。
- **调试模式**：设置环境变量 `SHION_DEBUG=1` 时，冷落、睡眠的阈值缩短为秒级，并在控制台输出状态变化日志；诗音旁显示 FPS，每 0.5 秒按实际经过时间统计桌宠 paintEvent 次数。计数器独立刷新、透明点穿、不抢焦点，跟随移动与大小变化且限制在屏幕内，随桌宠隐藏/关闭。普通模式不创建该窗口。它表示 Qt 绘制频率，不代表显示器呈现频率；定时器、render_frame 和计数器自身绘制不计入。保留静止画面的重绘优化，静止时 FPS 较低是正常现象。
- 程序日志写进 `%APPDATA%\Shion\shion.log`，不要大量打印到终端。
